# 인스타는 연결했는데 캠페인을 안 만든다 — 원인 분석 + 개선 아이디어

- **작성일**: 2026-09-10
- **근거**: 프로덕션 DB 전수 조회 + 프로덕션 액세스 로그 2일치(09-08 15:07 ~ 09-10 19:59, 125,052줄) + 프론트 코드 리딩 + 업계 자료
- **배경**: [무료체험 기간 분석](../ops/TRIAL_LENGTH_14_VS_30_ANALYSIS_2026-09-10.md)에서
  "연동까지 마친 70명 중 30일 안에 캠페인을 만든 사람이 50%뿐"이 나왔습니다.
  캠페인만 만들면 첫 DM은 **중앙값 0일** 만에 나가므로, 여기가 우리 활성화의 진짜 병목입니다.

---

## 0. 결론 3줄

1. **프론트 UI 가설이 맞습니다. 특히 모바일입니다.**
   2일 실측: 캠페인 목록을 연 계정 중 2일 내 캠페인을 만든 비율이
   **데스크톱 44.8% / 모바일 21.0%** — 모바일이 절반 이하입니다.
2. **두 번째 누수는 "다 만들어 줬는데 안 켜는 것"입니다.**
   캠페인이 0개인 IG 계정 460개 중 **415개(90.2%)가 이미 DM 이전 분석을 돌렸고**,
   그 결과 **바로 켤 수 있는 초안 542건이 51개 계정에 놓여 있습니다.** 적용률은 7%입니다.
3. **"게시물이 없어서"는 아닙니다.** 게시물 수가 조회된 84개 계정 중 0개인 계정은 13개(15.5%),
   중앙값은 54개입니다. 서버 오류도 아닙니다(2일간 생성 API 400 5건 / 409 1건).

## 1. 어디서 멈추는지 — 실측 퍼널

액세스 로그에 `ig_connection_id` 가 쿼리스트링으로 남아서, IG 계정 단위로 화면 이동을 따라갈 수 있었습니다.

| 단계 | 계정 수 | 비율 |
|---|---|---|
| 캠페인 목록 화면을 열었다 | **139** | 100% |
| → 게시물 선택(미디어 목록)까지 갔다 | **69** | **49.6%** |
| → 실제로 캠페인을 만들었다 | **43** | **30.9%** |

**캠페인 생성 API 결과(2일)**: `201` 63건 · `400` 5건 · `409` 1건
→ **서버가 막는 게 아닙니다.** 사람이 화면에서 멈춥니다.

가장 큰 낙차는 **목록 → 게시물 선택 사이(절반이 사라짐)** 입니다.
그 다음이 게시물 화면까지 간 69개 중 43개만 완주(62%)하는 구간입니다.

## 2. 가장 뚜렷한 갈림길 — 모바일

| | 계정 수 | 2일 내 캠페인 생성 |
|---|---|---|
| 모바일 우세 | **81개** | **17개 (21.0%)** |
| 데스크톱 우세 | 58개 | 26개 (**44.8%**) |

**트래픽의 다수(58%)가 모바일인데, 전환은 절반 이하입니다.**

업계 벤치마크와 비교하면 이건 "원래 모바일이 낮으니까"로 넘길 수 없는 격차입니다:

- 일반적으로 데스크톱 폼 완료율이 모바일보다 **9~11%p 높고**, 리드 폼은 모바일이 **약 32% 낮습니다**
  ([Reform](https://www.reform.app/blog/mobile-vs-desktop-form-performance-comparison),
  [Digital Applied](https://www.digitalapplied.com/blog/form-conversion-rate-benchmarks-2026-data-points))
- **우리는 53% 낮습니다** → 업계 평균 격차의 **1.6배**. 우리 UI 고유 문제가 얹혀 있습니다.

> → 이메일 리마인더로 되돌리는 게임이 아니라, **연동 성공 그 화면에서 바로 만들게 해야 합니다.**

## 4. 코드에서 확인된 구체적 병목 5개

### (a) 🔴 비활성 저장 버튼이 "왜 안 되는지" 말해주지 않는다

[CampaignEditorPage.tsx:489](../../../../TurnflowLink-dev/src/app/pages/dm-auto/CampaignEditorPage.tsx)
의 `isSubmitDisabled` 는 조건이 **7개**입니다.

```
게시물 미선택 / 키워드 조건 미선택 / DM 본문 비어있음 /
공개답글 켰는데 문구 없음 / 게이트 켰는데 보상메시지 없음 /
"특정 단어 포함" 켰는데 단어 0개 / 전송 중
```

이 값이 쓰이는 곳은 버튼의 `disabled` 속성 **두 군데뿐**(:503, :1197)이고,
**어떤 조건이 걸렸는지 알려주는 문구가 화면에 하나도 없습니다.**

더 나쁜 건, `handleSubmit` 안에는 사유별 `alert()` 가 다 준비돼 있는데(:380~404)
**버튼이 이미 잠겨 있어서 그 alert 가 뜰 기회가 없습니다.** 사용자가 보는 건 회색 버튼 하나입니다.

> 업계 정설: 비활성 버튼은 "왜"를 말할 수 없어서 UI가 고장난 것처럼 느껴집니다. 제출 시 검증하고
> 문제 필드로 안내하는 것이 정석입니다.
> ([Smashing Magazine](https://www.smashingmagazine.com/2021/08/frustrating-design-patterns-disabled-buttons/),
> [Adam Silver](https://adamsilver.io/blog/the-problem-with-disabled-buttons-and-what-to-do-instead/))

### (b) 🔴 모바일 저장 버튼이 긴 폼의 맨 끝에 있다 (고정 아님)

`:1193` — `<div className="pt-4 md:hidden">` 로 **폼 본문 마지막에 그냥 붙어 있습니다.**
sticky/fixed 가 아닙니다. 즉 모바일 사용자는:

1. 긴 폼을 끝까지 스크롤해서
2. 회색으로 잠긴 버튼을 발견하고
3. 왜 잠겼는지 모르는 채로

이탈합니다. 데스크톱은 우측 탭바에 컴팩트 버튼이 항상 보입니다(:500) — **두 플랫폼의 경험이 다릅니다.**

### (c) 🟠 DM 문구 입력란이 처음엔 화면에 없다

`:971` — 메시지 섹션은 `selectedPost && selectedComment` 일 때만 렌더됩니다.
게시물과 키워드 조건을 먼저 고르지 않으면 **"DM 문구를 쓰는 칸"이 아예 안 보입니다.**

첫 진입 화면이 "이 도구로 무엇을 하는지"를 보여주지 못합니다. 사용자는 게시물 목록만 보고
"여기서 뭘 하라는 거지?"에서 멈춥니다 — 이게 §1의 "목록 → 게시물 선택 사이 50% 이탈"과 맞물립니다.

### (d) 🟠 모바일은 편집/미리보기가 탭으로 갈라져 동시에 못 본다

`:1333` — 모바일은 상단 탭으로 `편집 | 미리보기` 를 전환합니다.
데스크톱은 480px 편집 패널 + 나머지 미리보기로 **동시에** 보입니다(:1351~1357).

즉 모바일에서는 **입력하면서 결과를 볼 수 없습니다.** "내가 만들고 있는 게 뭔지"에 대한 피드백이
끊기고, 이게 완주율을 떨어뜨립니다.

### (e) 🟠 템플릿·프리셋이 아예 없다

`src/app/pages/dm-auto/` 전체에 preset / 템플릿 갤러리 코드가 **0건**입니다.
빈 상태(`:341`)는 이렇게 생겼습니다:

```
[💬 아이콘]
캠페인이 없습니다
첫 번째 자동화 캠페인을 만들어보세요.
[ 새 캠페인 만들기 ]   ← outline 버튼 1개
```

> Canva는 빈 화면에 "템플릿으로 시작"을 붙여서 **첫 세션 생성률을 40% → 75%** 로 올렸습니다.
> 빈 상태는 어떤 온보딩 모달·투어보다 사용자가 자주 마주치는 화면입니다 — 하나만 투자한다면 여기입니다.
> ([Userpilot](https://userpilot.com/blog/best-user-onboarding-experience/))

참고로 **`any_media`(게시물을 안 고르는 모드)는 740개 캠페인 중 17개(2.3%)만 쓰입니다.**
게시물 선택이라는 관문을 우회할 수 있는 모드가 이미 있는데 사실상 아무도 못 찾고 있습니다.

## 5. 두 번째로 큰 누수 — 이미 만들어 둔 초안이 안 켜진다

이게 개발 대비 회수가 가장 큰 항목입니다.

### 5-1. 재고가 이미 쌓여 있다

| | 수치 |
|---|---|
| 캠페인 0개인 IG 계정 | **460개** |
| 그중 **DM 이전 분석을 이미 돌린** 계정 | **415개 (90.2%)** |
| 이전 분석이 찾아낸 후보 총계 | **13,334건** (auto_draft 2,684 / needs_review 881 / excluded 9,769) |
| 실제로 적용(apply)된 후보 | **249건 (전체 후보의 1.9%, 채택 가능 후보의 7%)** |
| **캠페인 0개 계정 중, 바로 켤 수 있는 초안을 가진 계정** | **51개 (초안 542건, 계정당 중위 3개·최대 117개)** |
| needs_review 까지 포함하면 | 77개 계정 / 704건 |

> **51개 계정 앞에 "누르면 켜지는 캠페인" 542건이 놓여 있는데 아무도 안 누릅니다.**

### 5-2. 적용해도 켜지지 않는다 — 단계가 하나 더 있어서

| 캠페인 출처 | 총계 | active | inactive/paused | **활성 비율** |
|---|---|---|---|---|
| 직접 만든 것 | 504개 | 428 | 76 (paused) | **84.9%** |
| **이전 초안 적용** | 236개 | 48 | **188 (inactive)** | **20.3%** |

이전 초안은 설계상 `apply` 하면 **INACTIVE 상태로 생성**되고, 활성화가 별도 단계입니다
([DM_CAMPAIGN_MIGRATION_FRONTEND.md](DM_CAMPAIGN_MIGRATION_FRONTEND.md) 참고).
그 한 걸음 때문에 **적용까지 해낸 사람의 80%가 그 자리에서 멈춥니다.**

> 업계 자료: 활성화 마일스톤이 4단계를 넘어가면 그 뒤는 제품 설계가 아니라 **사용자 의지**에
> 의존하게 됩니다. 어떤 분석 SaaS는 연동·초대·대시보드 설정을 강제하다 활성화율 18%였는데,
> 샘플 데이터를 넣고 연동을 선택사항으로 바꾸자 **44%** 가 됐습니다.
> ([Tandem](https://usetandem.ai/blog/activation-rate-benchmarks-in-app-guidance))

## 7. 개선 아이디어 — 회수 큰 순서

### 🥇 A. 이미 쌓인 재고를 판다 (개발 최소 / 회수 즉시 / A·B 불필요)

| # | 아이디어 | 근거 |
|---|---|---|
| **A-1** | **빈 상태를 "초안 카드 목록"으로 바꾼다.** "캠페인이 없습니다" 대신 이미 찾아둔 후보를 카드로 깔고 `[이대로 시작하기]` 버튼을 붙인다 | 51개 계정 × 542건 재고. Canva 40%→75% 사례 |
| **A-2** | **`apply` 를 바로 ACTIVE 로** (또는 `[적용하고 바로 시작]` 단일 버튼). 지금은 apply 후 활성화가 또 한 단계 | 이전 초안 활성률 20.3% vs 직접생성 84.9% |
| **A-3** | 초안이 놓인 51개 계정에 **인앱 배너 + 메일 1회**: "예전 도구에서 쓰던 캠페인 N개를 찾아뒀어요" | 90.2%가 이미 분석을 돌린 상태 |
| **A-4** | 목록 화면에 초안 개수 배지 노출 (지금도 프론트가 `?status=inactive&source=dm_migration` 을 조회하고는 있는데 눈에 안 띈다) | 액세스 로그에서 이 호출 확인됨 |

### 🥈 B. 모바일 에디터 수술 (모바일이 트래픽 58%인데 전환 절반)

| # | 아이디어 | 근거 |
|---|---|---|
| **B-1** | **저장 버튼을 sticky bottom 으로.** 스크롤 위치와 무관하게 항상 보이게 | `:1193` 현재 폼 맨 끝 고정 아님 |
| **B-2** | **버튼을 잠그지 말고 누르게 한다.** 누르면 부족한 항목으로 스크롤 + 하이라이트 + 그 자리 오류 문구 | `isSubmitDisabled` 7조건·안내 0개. handleSubmit 의 alert 가 이미 있어서 **구현 비용도 낮다** |
| **B-3** | 버튼 위에 **부족 항목 체크리스트 상시 표시** ("게시물 선택 ✓ / 키워드 조건 ✗ / DM 문구 ✗") | 사용자가 남은 일을 세어볼 수 있게 |
| **B-4** | 모바일에서 미리보기를 탭 대신 **상단 미니 프리뷰로 상주** (탭하면 확대) | `:1333` 탭 전환으로 피드백 끊김 |
| **B-5** | 필수 입력을 2~3스텝으로 쪼갠다 (게시물 → 문구 → 확인) + 진행바 | 멀티스텝이 같은 필드 수 기준 완료율 **+14%**, 리드 폼은 **+21%** ([Digital Applied](https://www.digitalapplied.com/blog/form-conversion-rate-benchmarks-2026-data-points)) |

### 🥉 C. 첫 캠페인을 "쓰기"가 아니라 "고르기"로

| # | 아이디어 | 근거 |
|---|---|---|
| **C-1** | **템플릿 3~5종** (링크 보내기 / 쿠폰 코드 / 팔로우 후 자료 / 사전예약 / 상담 연결). 고르면 문구·키워드가 채워진 상태로 에디터 진입 | 프리셋 코드 현재 0건. ManyChat도 첫 화면이 프리빌트 템플릿 갤러리 ([Manychat](https://manychat.com/blog/new-manychat-templates-for-chatbots/)) |
| **C-2** | **최신 게시물을 기본 선택**해두고 "다른 게시물로 바꾸기"를 부가 동작으로 | 게시물 선택이 50% 이탈 지점 |
| **C-3** | `any_media`(모든 게시물) 모드를 **첫 화면 기본 후보**로 승격 — 게시물 고르기 관문을 아예 없앨 수 있다 | 740개 중 17개(2.3%)만 사용 = 아무도 못 찾음 |
| **C-4** | **AI 초안을 기본 채움**으로 (지금은 사용자가 버튼을 눌러야 함). `ai-suggest` 는 2일 98회 호출될 만큼 이미 쓰인다 | 다만 `diversify-opening`(문구 회전 변형)은 **저장까지 간 캠페인이 740개 중 2개(0.3%)** — 눌러보고 안 쓰는 상태 |
| **C-5** | 게시물이 0개인 계정(15.5%)에는 **샘플 게시물로 미리보기**만이라도 보여준다 | 연동만 하고 아무것도 못 보는 상태를 없앤다 |

## 9. 검증 방법

- **핵심 지표**: "연동 후 24시간 내 첫 캠페인 생성률"
  현재 기준선 — **데스크톱 44.8% / 모바일 21.0%**
- **1차 목표**: 모바일을 데스크톱의 80% 수준(**약 35%**)까지 끌어올린다
- A안(재고 판매)은 대상이 51개 계정으로 특정되니 **A/B 없이 before/after** 로 충분합니다
- B·C안은 모바일 사용자만 A/B. 2일에 모바일 81개 계정이 목록을 여니 **각 군 200개 계정 = 약 2주** 면 모입니다
- 반드시 함께 볼 것: **생성된 캠페인이 실제로 active 가 되는 비율** (만들기만 하고 안 켜면 의미 없음)
