### ① 신규 가입자 — 인증 강제 `/signup/phone`

가입(이메일·구글·카카오·인스타) 직후, `phone_verification_required === true`인 동안
**벗어날 수 없는** 화면.

```
┌────────────────────────────────────────────┐
│  휴대폰 번호를 인증해 주세요                   │
│  가입 확인을 위해 한 번만 거치는 단계예요        │
│                                            │
│  [ 010-1234-5678      ]  [ 인증번호 받기 ]    │
│  [ 000000 ]  02:47 남음      [ 재발송 (47) ]  │
│                                            │
│  ☐ (선택) 혜택·이벤트 등 광고성 정보 수신 동의  │
│          (문자 메시지)                       │
│                              [ 확인 ]        │
└────────────────────────────────────────────┘
```

**라우팅 가드**: `required === true` && 현재 경로 ≠ `/signup/phone` → 리다이렉트.

> 🔑 **경로를 `/signup/phone`으로 해주세요.** 이 화면의 URL과 캡처를 카카오 동의항목
> 심사에 제출합니다. 카카오는 *"실제 회원가입 페이지에서 전화번호를 수집하는 경우만"*
> 승인하므로, `/settings/...` 아래면 심사가 반려될 수 있습니다. 화면 제목에도 "회원가입"
> 맥락이 보이면 좋습니다.

### ② 기존 회원 — 보상 팝업

```
┌──────────────────────────────────────────────┐
│  📱 휴대폰 등록하고 프로 체험 7일 더 받기        │
│                                              │
│  번호를 인증하면 바로 적용돼요.                  │
│  (1분이면 끝나요)                              │
│                                              │
│      [ 나중에 하기 ]    [ 등록하고 받기 ]        │
└──────────────────────────────────────────────┘
```

**노출 조건 — 전부 서버 값으로 판단하세요:**
```ts
const s = await getPhoneStatus();              // GET /auth/me/phone/
const show = !s.phone_verified && !s.required && s.reward.kind !== 'none';
```

**문구는 `reward`에서 가져오세요 — 하드코딩 금지:**

| `reward.kind` | 문구 |
|---|---|
| `trial_extended` | "프로 체험이 **{days}일** 늘어나요" (현재 7일) |
| `trial_granted` | "프로 체험 **{days}일**이 시작돼요" (현재 30일 — 문구가 다릅니다!) |
| `none` | **팝업을 띄우지 마세요** |

> ⚠️ `days`를 7로 하드코딩하면 `trial_granted`(30일) 사용자에게 **틀린 숫자**를 보여줍니다.
> `kind === 'none'`인데 보상 문구를 띄우면 **없는 혜택을 약속하는 것**이고요.

**노출 빈도**는 기존 `popup_state`(`GET/PATCH /auth/me/popup-state/`)를 재사용하세요 —
기기 간 동기화됩니다. 제안 키 `phone_collect`, 규칙 `최대 3회 · 닫으면 7일 뒤 재노출 ·
등록 완료 시 영구 중단`.

### ③ 설정 — 내 정보

- 미등록: "휴대폰 등록" 버튼 → ①과 같은 입력 컴포넌트
- 등록됨: `010-****-5678` + [변경] (새 번호로 재인증) / [삭제]

## 4. ⭐ dev에서 인증을 끝까지 도는 법

**dev는 실제 문자가 가지 않습니다**(`SMS_MOCK_MODE=True`). 그리고 인증번호는 서버에
**평문으로 저장되지 않습니다**(HMAC). 그래서 **발송까지만 되고 확인 단계를 돌 수 없습니다.**

이걸 풀려고 dev 전용 API를 하나 뒀습니다. **인증번호는 항상 `123456`입니다.**

```
① POST /api/v1/auth/me/phone/          { "phone": "010-1234-5678" }      → 202
② POST /api/v1/auth/dev/phone-code/    { "email": "p01-...@..." }        → { "code": "123456" }
③ POST /api/v1/auth/me/phone/verify/   { "code": "123456" }              → 200
```

②는 자동화 테스트에서도 그대로 쓰세요. 인증 불필요합니다.

> 이 API는 평문을 "읽어오는" 게 아니라 대기 중인 인증 행의 **해시를 알려진 값으로 덮어씁니다.**
> 저장 모델(평문 미보관)은 운영과 dev가 **완전히 같습니다** — dev 전용 저장 분기를 만들면
> 그게 언젠가 운영으로 샙니다.

**②를 건너뛰고 ③을 호출하면 `400 PHONE_CODE_INVALID`가 납니다.** 발송 직후 바로 호출하세요
(인증번호 수명 3분).

## 5. 에러 처리 — 여기가 제일 중요합니다

> ⚠️ 이 프로젝트는 **같은 실수를 두 번** 겪었습니다. 추가 IG 계정 견적의 `QuoteGate`가
> 400 사유를 버리고 "잠시 후 다시 시도"로 뭉개서 고객이 3분간 8회 재시도했고(CS #d34572b3),
> 탈퇴 모달도 401 외 전부를 generic으로 덮어 백엔드가 보낸 사유가 화면에 닿지 못했습니다
> (CS #247995c5). **여기서 반복하면 "인증번호가 안 와요" CS가 원인 불명으로 쌓입니다.**

모든 오류는 `detail`(사람이 읽을 문구) + `code`(머신 키)를 **함께** 냅니다.
**분기는 `code`로, 표시는 `detail`로** 하면 서버 문구 수정이 프론트 배포 없이 반영됩니다.

```ts
const res = await fetch(url, opts);
if (!res.ok) {
  const e = await res.json().catch(() => ({}));
  switch (e.code) {
    case 'PHONE_RESEND_TOO_SOON': return startCountdown(e.retry_after);   // 토스트 말고 버튼 비활성
    case 'PHONE_CODE_INVALID':    return setHint(`${e.attempts_left}회 남았습니다`);
    default:                      return setError(e.detail ?? '잠시 후 다시 시도해 주세요.');
    //                                              ^^^^^^^ detail을 먼저 쓸 것
  }
}
```

### 발송 `POST /auth/me/phone/`

| HTTP | `code` | 화면 |
|:-:|---|---|
| 400 | `PHONE_INVALID` | 입력란 아래 `detail` (국내 휴대폰만 허용) |
| 400 | `PHONE_ALREADY_VERIFIED` | "이미 등록된 번호예요" |
| 429 | `PHONE_RESEND_TOO_SOON` | **`retry_after`초 카운트다운** |
| 429 | `PHONE_DAILY_LIMIT` | "오늘은 더 받을 수 없어요" + 고객센터 |
| 429 | `PHONE_IP_LIMIT` | `detail` 그대로 |
| 429 | (code 없음) | 스로틀 5회/시간 |
| 502 | `SMS_SEND_FAILED`·`SMS_UNAVAILABLE` | **재시도 버튼** |
| 503 | `SMS_CAPACITY_EXCEEDED` | 운영 사고 — 고객센터 안내 |

### 확인 `POST /auth/me/phone/verify/`

| HTTP | `code` | 화면 |
|:-:|---|---|
| 400 | `PHONE_CODE_INVALID` | **`attempts_left`회 남음**. 0이면 재발송 버튼으로 전환 |
| 400 | `PHONE_CODE_EXPIRED` | "만료됐어요" → 재발송 |
| 400 | `NO_PENDING_PHONE_VERIFICATION` | 발송 단계로 복귀 |
| 429 | (code 없음) | 스로틀 10회/분 |

| 상황 | 서버가 주는 값 | 프론트 |
|---|---|---|
| 카카오 가입 + 심사 **미승인** | `required: true` | 인증 화면 표시 |
| 카카오 가입 + 심사 **승인 후** | `required: false` | **자동으로 스킵** |

판정은 **번호를 들고 있느냐 하나만** 봅니다 — 가입수단을 보지 않습니다. 그래서 **`required`
값만 읽으면 분기가 필요 없습니다.** (이게 깨지지 않도록 백엔드에 회귀 테스트를 박아뒀습니다.)

승인되면 `phone_source`가 `"kakao"`로 내려옵니다. 설정 화면에서 *"카카오계정에서 가져온
번호"*라고 표기해 주면 사용자가 덜 당황합니다.

## 8. 배포 순서 — 이 순서를 지켜주세요

```
① 백엔드 API 배포              ✅ 완료 (현재 무변화 상태)
② 프론트 화면 배포             ← 지금 작업
③ 백엔드가 PHONE_REQUIRED_SINCE 설정  ← 여기서 수집 시작
④ 카카오 전화번호 동의항목 신청  (②의 가입화면 URL·캡처 필요)
```

> ⚠️ **③을 ②보다 먼저 하면 안 됩니다.** 화면이 없는 상태에서 `required: true`를 내리면
> 장애는 안 나지만("프론트가 무시") "필수인데 아무도 안 한" 구간이 지표에 남습니다.
>
> ✅ **①과 ② 사이는 안전합니다.** 새 필드는 전부 추가(additive)라 기존 화면이 깨지지 않습니다.
