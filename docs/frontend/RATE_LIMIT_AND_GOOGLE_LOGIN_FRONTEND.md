# [백엔드 → 프론트] 429 두 종류 구분 + 구글 로그인 응답 1개 추가

작성 2026-08-12 · 마이그레이션 없음 · **기존 동작 변경 없음(추가만)**

보안 감사 대응으로 두 가지가 바뀝니다. 둘 다 **새 응답이 추가되는 것뿐**이고,
지금 화면이 그대로 동작하던 경로는 하나도 바뀌지 않습니다.

|---|---|---|

## 1. 🔴 429 가 두 종류가 됐습니다 — 반드시 분기해 주세요

### 왜 중요한가

지금 프론트는 **429 를 받으면 무조건 "요금제 한도 초과"** 로 처리해 유료 전환 모달을 띄우고
`paywall_viewed` 분석 이벤트를 발사하도록 돼 있습니다.

여기에 이번에 **속도 제한(rate limit) 429** 가 새로 생깁니다. 분기하지 않으면
**"요청이 너무 잦습니다" 를 "돈 내세요" 로 잘못 안내**하게 되고, 더 큰 문제로
**paywall 분석 데이터에 가짜 숫자가 섞여 되돌릴 수 없게 됩니다.**

### 응답 형태

두 응답 모두 **HTTP 429** 지만 `error.code` 로 완전히 갈립니다.

**① 요금제 한도 초과 (기존 — 변경 없음)**

```json
{
  "success": false,
  "error": {
    "code": "PLAN_LIMIT_EXCEEDED",
    "message": "플랜 사용량 한도를 초과했습니다",
    "details": { "metric": "dm", "current": 100, "limit": 100, "plan": "free" }
  }
}
```

**② 속도 제한 (신규)**

```json
{
  "success": false,
  "error": {
    "code": "RATE_LIMITED",
    "message": "요청이 너무 잦습니다. 잠시 후 다시 시도해 주세요.",
    "details": { "code": "RATE_LIMITED", "retry_after": 43 }
  }
}
```

- `retry_after` — **초 단위**. 이 시간 뒤에 재시도하면 됩니다. 올림 처리돼 있어 그대로 쓰면 됩니다.
- 아주 드물게 서버가 대기 시간을 계산 못 하면 **`retry_after` 키가 없습니다** → 없을 때를 대비해 주세요.

### 분기 예시

```ts
if (res.status === 429) {
  const code = body?.error?.code;

  if (code === "RATE_LIMITED") {
    // ⚠️ paywall 모달 띄우지 말 것 · paywall_viewed 발사하지 말 것
    const sec = body?.error?.details?.retry_after;
    toast(sec ? `요청이 너무 잦습니다. ${sec}초 후 다시 시도해 주세요.` : "요청이 너무 잦습니다. 잠시 후 다시 시도해 주세요.");
    return;
  }

  // 기존 경로 그대로
  openPaywallModal(body.error.details);
  track("paywall_viewed", { ... });
}
```

> **주의**: `error.code` 로만 판단해 주세요. `message` 문구는 나중에 다듬을 수 있습니다.

### 어디서 발생하나

지금은 **AI 생성 엔드포인트 2곳**에만 걸려 있습니다.

| 엔드포인트 | 화면 |
|---|---|
| `POST /api/v1/ai/classify-posts/` | 게시물 자동 분류 |
| `POST /api/v1/integrations/auto-dm-campaigns/ai-suggest/` | 캠페인 AI 제안 |

### 상한 — 정상 사용자는 만날 일이 없습니다

| 플랜 | 시간당 | 하루 |
|---|---:|---:|
| 유료(베이직·프로) | 100회 | **400회** |
| 무료 | 15회 | 40회 |

실측(2026-08-12 기준 최근 7일): **가장 많이 쓰는 고객이 하루 2.3건**입니다.
유료 상한은 그 **약 170배**라 실제로 걸릴 일이 없습니다. 어뷰즈(무료 가입 후 스크립트)만 막는 게 목적입니다.

> 그래도 정상 사용자가 걸린다는 제보가 오면 알려주세요 — 환경변수로 즉시 올릴 수 있습니다
> (`THROTTLE_AI_PAID_HOUR` / `THROTTLE_AI_PAID_DAY`, 재배포 불필요).

### 앞으로 늘어납니다

같은 `RATE_LIMITED` 형태로 **공개 엔드포인트 등에도 순차 적용**할 예정입니다.
지금 `error.code` 기준으로 **공용 처리**를 만들어 두시면 그때 추가 작업이 없습니다.

## 2. 🟠 구글 로그인 — 드문 403 하나가 추가됩니다

### 무엇이 바뀌나

구글이 보내주는 ID 토큰에는 **`email_verified`**(이 이메일이 본인 것임을 구글이 확인했는지)가
들어 있는데, 지금까지 서버가 그 값을 **읽지 않고** 이메일만으로 기존 계정에 로그인시켰습니다.
→ 공격자가 자기 소유 도메인으로 워크스페이스를 만들어 남의 이메일을 적어 넣으면
**계정을 통째로 가져갈 수 있었습니다.**

### 정상 사용자에게는 아무 변화가 없습니다

- 일반 지메일 계정은 `email_verified` 가 **항상 `true`** 입니다.
- **화면·클릭·인증 메일 어느 것도 늘지 않습니다.** OAuth 의 이점은 그대로입니다.
- 로그인을 거절하는 게 아니라, **미확인 토큰이 기존 계정에 붙는 것만** 막습니다.

| 구글이 보낸 값 | 서버 동작 |
|---|---|
| `email_verified: true` | **종전과 100% 동일** |
| `false` + 그 이메일의 계정 **없음** | 신규 가입 진행 (단 `is_email_verified` 는 `false` 로 둠) |
| `false` + 그 이메일의 계정 **있음** | **403** (아래) |

### 새 응답

```
HTTP 403 Forbidden
{
  "detail": "이 이메일로 가입된 계정이 이미 있습니다. 구글에서 이메일 소유 확인이 완료되지 않아 자동 연결할 수 없습니다. 비밀번호로 로그인하거나 이메일 인증을 완료해 주세요.",
  "code": "GOOGLE_EMAIL_UNVERIFIED"
}
```

**조치**: `code === "GOOGLE_EMAIL_UNVERIFIED"` 이면 위 `detail` 을 그대로 보여주시고,
**"비밀번호로 로그인" CTA** 를 함께 노출해 주시면 좋겠습니다.

> 배포 전 실측: 전체 회원 148명 중 **같은 이메일을 쓰는 계정이 0쌍**입니다.
> 즉 **현재 회원 중 이 403 을 만날 사람은 없습니다.** 서버에 계측 로그를 넣어 두었으니
> 실제로 이 경로가 발생하면 저희가 먼저 확인해 알려드리겠습니다.

## 3. 바뀌지 않은 것 (확인용)

혹시 몰라 명시합니다 — 아래는 **전부 그대로**입니다.

- 로그인 토큰 형식·수명 (RS256, access 1일) — CS 워커·어드민 콘솔 포함 변경 없음
- 기존 429(`PLAN_LIMIT_EXCEEDED`) 의 응답 형태와 발생 조건
- 구글 로그인 성공 응답(`user` + `tokens`) 형태
- 그 외 모든 엔드포인트의 요청·응답 스키마

DB 마이그레이션도 없습니다.
