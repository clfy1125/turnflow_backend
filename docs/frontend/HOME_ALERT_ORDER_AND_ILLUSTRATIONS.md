# 홈 화면 — 무엇을 어떤 순서로 보여주는가

작성 2026-09-21 · 대상: 프론트엔드 · 디자이너 · 기획
API 규격은 `HOME_V2_ALERTS_FRONTEND.md` 를 보세요. 이 문서는 **무엇이 언제 뜨고, 왜 그 순서인지**를 정리한 것입니다.

---

## 0. 세 줄 요약

1. 홈은 **「지금 이 상태인가」를 매번 계산**합니다. 알림을 쌓아두지 않으므로, 문제가 해결되면 배너가 저절로 사라집니다.
2. 순서는 **서버가 정합니다**(`rank`). 웹과 앱이 갈리지 않도록 프론트에서 다시 정렬하지 마세요.
3. 총 **17개 상태 + 강제 모달 1개**. 일러스트는 **7종**으로 묶어서 씁니다.

---

## 1. 순서의 원칙

> **돈이 새는 순 → 사용자가 지금 손쓸 수 있는 순**

이 두 가지가 순서를 정하는 전부입니다. 그래서:

- 결제 실패가 제일 위입니다. 방치하면 7일 뒤 무료 플랜으로 강등됩니다.
- **발송 일시제한은 같은 심각도 안에서 아래로 내립니다.** 기다리면 자동으로 풀려서 사용자가 할 일이 없기 때문입니다. 위에 둬 봐야 불안만 만듭니다.
- 권유(할 일 제안)는 장애가 아니므로 전부 그 아래입니다.

---

## 2. 전체 목록 (위에서부터 뜨는 순서)

### 🔴 critical — 자동화가 실제로 멈춰 있음 · **닫기 불가**

닫을 수 있게 하면 알림의 의미가 없습니다. 해결되면 자동으로 사라집니다.

| 순위 | 코드 | 이럴 때 뜹니다 | 그림 |
|:--:|---|---|---|
| 10 | `payment_failed` | 결제가 실패해 미납 상태 | `quota-billing` |
| 20 | `ig_disconnected` | 인스타 연결이 끊김(토큰 만료·오류) | `blocked` |
| 40 | `comment_stream_down` | 새 댓글이 안 들어옴 — 웹훅이 끊겼고 **자동 재구독마저 실패** | `blocked` |
| 50 | `dm_quota_exhausted` | 이번 달 DM 한도 소진 — 넘어온 댓글이 **조용히 버려지는 중** | `quota-billing` |
| 60 | `campaign_post_restricted` | 게시물이 막혀 그 캠페인만 자동 정지 | `blocked` |
| 70 | `dm_send_blocked` | 인스타가 계정 전체 발송을 막음 — **기다리면 자동 재개** | `blocked` |
| 80 | `ig_account_disabled` | 쓸 수 있는 자리가 남는데 꺼져 있는 계정이 있음 | `blocked` |

### 🟡 warning — 멈추진 않았지만 새고 있음 · **닫기 불가**

| 순위 | 코드 | 이럴 때 뜹니다 | 그림 |
|:--:|---|---|---|
| 100 | `dm_quota_warning` | 이번 달 한도의 **80% 이상** 사용 | `quota-billing` |
| 110 | `subscription_ending` | 해지 예약됨 — 아직 기간은 남음 | `quota-billing` |

### 🔵 todo — 장애가 아니라 권유 · **닫기 가능**

닫으면 서버에 기록됩니다(`HomeAlertDismissal`). **대상 단위로 기억**하므로, 새 게시물이 올라오면 같은 종류라도 다시 뜹니다.

| 순위 | 코드 | 이럴 때 뜹니다 | 그림 |
|:--:|---|---|---|
| 200 | `recent_post_no_campaign` | **최근 7일 내** 올린 게시물에 자동 DM 이 없음 | `campaign-setup` |
| 210 | `create_campaign` | 자동 DM 이 **아직 하나도 없음** | `campaign-setup` |
| 220 | `link_page_empty` | 링크 페이지가 없거나 · 비었거나 · 비공개 | `link-page` |
| 230 | `report_ready` | 계정 분석 리포트가 나옴 | `report` |
| 231 | `report_running` | 리포트 생성 중 | `report` |
| 232 | `report_failed` | 리포트 생성 실패 | `report` |
| 240 | `migration_review_pending` | 다른 툴에서 불러온 캠페인이 검수 대기 중 | `migration-review` |

### ⚪ 기본 상태 — 알릴 게 하나도 없을 때

| 순위 | 코드 | 이럴 때 뜹니다 | 그림 |
|:--:|---|---|---|
| 999 | `create_campaign` (`data.is_default = true`) | 캠페인이 **이미 있고** 다 잘 돌아가는 중 | `all-good` |

> 같은 `create_campaign` 코드가 **두 자리**에 등장합니다.
> `data.is_default` 가 `false` 면 「만들어 보세요」(순위 210), `true` 면 「잘 돌고 있어요」(순위 999)입니다.
> 이것만 `todo` 인데도 **닫을 수 없습니다** — 닫으면 홈이 통째로 비기 때문입니다.

### ⬛ 강제 모달 — 배너가 아닙니다

| 코드 | 이럴 때 | 그림 |
|---|---|---|
| `ig_account_selection_required` | 쓸 수 있는 계정 수보다 연동된 계정이 많아 **골라야 넘어감** | 없음 |

응답의 `blocking` 필드로 따로 내려옵니다. `alerts` 배열에 섞여 있지 않습니다.

## 3. 일러스트 7종

17개 상태를 그림 7장으로 묶었습니다. 상태마다 한 장씩 그리면 18장이 되는데, **사용자가 할 일이 같으면 그림도 같아야** 화면이 일관됩니다.

| 그림 | 묶은 기준 | 몇 개 상태 |
|---|---|:--:|
| `campaign-setup` | 자동 DM 을 만들어야 함 | 2 |
| `all-good` | 다 잘 돌고 있음 | 1 |
| `link-page` | 링크 페이지를 채워야 함 | 1 |
| `report` | 리포트 (생성 중·완료·실패) | 3 |
| `migration-review` | 불러온 캠페인을 검수해야 함 | 1 |
| `quota-billing` | **돈 문제로 멈춤** | 4 |
| `blocked` | **그 밖의 이유로 DM 이 못 나감** | 5 |

### 짝으로 쓰는 두 장

`all-good`(보라 · 체크)과 `blocked`(빨강 · X)는 **같은 말풍선에 배지만 다른 한 쌍**입니다.
사용자가 며칠 사이에 번갈아 보게 되므로 **같은 자리, 같은 크기**로 배치해 주세요. 그래야 설명 없이도 "정상 ↔ 문제"가 읽힙니다.

### 매핑 코드

```ts
import manifest from "@/assets/home-illustrations/manifest.json";

export function illustrationFor(alert: HomeAlert): string | null {
  // 유일한 예외 — 같은 코드가 상황에 따라 두 그림으로 갈립니다
  if (alert.code === "create_campaign") {
    return alert.data?.is_default ? "all-good" : "campaign-setup";
  }
  return manifest.alert_code_map[alert.code] ?? null;
}
```

## 4. 일부러 안 만든 것

되살리자는 얘기가 나오기 쉬운 것들이라 이유를 남겨 둡니다.

**「자동 DM N개가 멈춰 있어요」 (시안 ④)** — 뺐습니다.
서버가 세는 '조치 필요'는 캠페인 개수가 아니라 **개별 발송의 미확인 건수**입니다. 그대로 쓰면 잘 돌고 있는 캠페인에 "멈춤" 딱지가 붙습니다.

**체험 D-3 예고 · 토큰 만료 예고 · 축소 예약 · 대기열 적체 등 8종** — `HOME_V2_ALERTS_FRONTEND.md` §10 에 이유와 함께 박제돼 있습니다. **되살리기 전에 그 이유부터 확인해 주세요.**

## 5. 구현할 때 주의

**서버는 문장을 만들지 않습니다.** `code`(머신 키)와 `data`(숫자·시각)만 내려갑니다. 문장은 프론트 i18n 이 만듭니다 — 서버가 완성된 한국어를 내리면 다국어가 막히고, 문구 하나 고치는 데 백엔드 배포를 기다려야 합니다.

**홈은 인스타 API 를 부르지 않습니다.** 홈은 전 사용자의 첫 화면이라, 여기서 Meta Graph 를 부르면 회사 전체가 나눠 쓰는 호출 한도를 태워 **다른 워크스페이스의 댓글 수집과 DM 발송이 굶습니다.** 최신 게시물·웹훅 상태는 서버가 1시간마다 미리 조회해 DB 에 적어 둔 값을 읽습니다. 그러니 **60초 폴링은 마음 놓고 하셔도 됩니다**(서버가 30초 캐시를 둡니다).

**닫기는 대상 단위입니다.** `dismiss_key` 를 그대로 돌려주세요. 같은 코드라도 대상(게시물·페이지 등)이 바뀌면 다시 떠야 정상입니다.
