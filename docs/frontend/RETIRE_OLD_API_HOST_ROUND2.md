## 1. §3 요청 ① — 이관 완료. 다만 목적지를 R2 로 바꿨습니다

### 왜 신 API 호스트가 아니라 R2 인가

요청서엔 "새 호스트로" 라고 쓰셨지만, **`media.turnflow.clfy.ai.kr`(R2 CDN)** 로 보냈습니다.

- 백엔드의 `MEDIA_URL` 은 **이미** R2 입니다. 2026-05 이후 업로드는 전부 여기로 가고 있습니다
  (여러분이 실측한 `@jageummaster` 의 `avatar_url` 이 그 증거입니다).
  옛 데이터만 R2 를 안 거치고 있었던 것이라, R2 로 보내는 게 **원래 규격으로 되돌리는 것**입니다.
- **§3 ② 에서 걱정하신 게 원천 제거됩니다.** "R2 로 옮기며 옛 로컬 미디어를 정리하면 그때 깨진다" —
  이제 데이터가 R2 를 직접 가리키므로, 오리진의 로컬 미디어를 언제 정리하든 무관합니다.
- CDN 이라 오리진(우리 서버)을 타지 않습니다. 신 API 호스트로 보내면 이미지 트래픽이 계속 오리진을 칩니다.
- 여러분 `image-src.ts` 기준으로도 `media.*` 는 "내부"로 분류돼 **`/image-proxy` 를 안 거칩니다**
  (회신 §3 의 분류 설명 기준). 리다이렉트 왕복도, Worker 경유도 없어집니다.

```
전  https://api.turnflow.clfy.ai.kr/media/pages/2026/03/베러.jpg      (308 → 오리진)
후  https://media.turnflow.clfy.ai.kr/pages/2026/03/베러.jpg          (R2 CDN 직결)
```

### 무엇을 바꿨나

| 대상 | 행 | URL |
|---|---:|---:|
| `pages.Block.data` | 57 | 91 |
| `pages.Page.data` | 3 | 3 |
| `ai_jobs.AiJob.result_json` | 1 | 7 |
| **합계** | **61** | **101** |

키는 회신에 적어주신 그대로였습니다 — `links[].thumbnail_url` · `thumbnail_url` · `images[]` ·
`avatar_url` · `cover_image_url` · `design_settings.backgroundImage`.
블록 종류는 `single_link`(썸네일)와 `profile`(아바타·커버) 둘뿐이었습니다.

**영향 페이지 19개 중 공개(라이브)는 12개**, 나머지 7개는 비공개 초안이었습니다.

### 남긴 것 (의도적)

`ai_jobs.AiJob` 의 `resolved_prompt` 5행 · `input_payload` 5행은 **그대로 뒀습니다.**
이건 2026-04~05 에 LLM 에 **실제로 보낸 프롬프트와 요청 본문의 기록**입니다. 화면에 렌더되지도,
재적용되지도 않습니다. 감사 기록을 사후 편집하면 "그때 무엇을 보냈는지"가 거짓이 되므로 건드리지 않았습니다.
(재적용 경로가 있는 `result_json` 1행은 이관 대상에 포함했습니다.)

### 검증 (4중, 전부 통과)

| # | 검증 | 결과 |
|---|---|---|
| 1 | 전 모델·전 컬럼 재스캔 | `pages.*` **0행** (남은 10행은 위 감사 기록) |

작업 전 상태는 전 행 통째로 백업했습니다(`/root/backups/media_url_before_*.json`).

## 2. ⚠️ 지금 조치가 필요한 것 — `387b7ce` 가 운영에 없습니다

회신을 받고 배포 상태를 확인했는데, Cloudflare Pages `turnflowlink` 기준으로:

```
Production (main)   183c4bb   2026-08-08   "fix(marketing): 라우트 전환 PageView 는 Meta 자동 추적에 맡긴다"
Preview    (dev)    387b7ce                "fix(deploy): 서버측이 아직 은퇴한 옛 API 호스트를 부르던 문제"
                              ^^^^^^^^^^^^ 이 수정이 dev 브랜치에만 있습니다
```

그래서 지금 이 순간에도 옛 호스트로 계속 들어옵니다. 우리 액세스 로그(오늘):

```
08-10 09:16:14  turnflowlink.pages.dev  GET 308  /api/v1/pages/@yujeongyaksa/
08-10 09:46:50  turnflowlink.pages.dev  GET 308  /api/v1/pages/@sowondream/
   → 오늘만 42건, 08-09 는 180건
```

**`dev` → `main` 머지·배포를 부탁드립니다.** 그 전까지는 DNS A 레코드를 지울 수 없습니다.
(지금 지우면 SSR OG fetch 가 실패해 `/@slug` 의 OG 태그가 기본값으로 떨어집니다.)

배포되면 알려주세요 — 저희가 `Cf-Worker` 건수 0 을 확인하고 2~3일 뒤 DNS 를 정리하겠습니다.

## 3. §2① 어드민 콘솔 — 저희가 확인해서 종결했습니다

"이 레포가 아닙니다" 가 맞았습니다. 확인해 보니 **이미 닫혀 있었습니다**:

| 확인 | 결과 |
|---|---|
| 워커 런타임 변수 | 비어 있음 — 오염원 아님 |
| 빌드 변수 `NEXT_PUBLIC_API_URL` | `https://turnflow-api.clfy.ai.kr/api/v1` ✅ |
| 어드민 레포 코드 | 옛 호스트 하드코딩 **0건** (`src/lib/env.ts` 가 env 만 읽음) |
| **라이브 번들 실측** (청크 27개 전수) | 옛 호스트 **0개 파일** · 신 호스트 2개 ✅ |
| 로그 | 마지막 호출 **08-07 11:17**, 이후 3일간 **0건** |

**왜 08-04 에 고쳤는데 08-07 까지 계속 왔나** — 빌드 변수는 *다음 빌드부터* 적용됩니다.
그 사이 배포 `409f6798`(08-05)은 **로컬 `npx wrangler deploy`** 였고, 그건 대시보드 빌드 변수를
읽지 않고 로컬 `.env` 를 씁니다. 08-07 의 GitHub 빌드가 돌면서 비로소 신 호스트가 박혔습니다.

> 여러분이 `.env.production`(레포↔대시보드 갈림)을 정리하신 것과 정확히 같은 함정입니다.
> **수동 wrangler 배포는 대시보드 변수를 우회합니다** — 어드민 쪽에도 공유해 두겠습니다.
