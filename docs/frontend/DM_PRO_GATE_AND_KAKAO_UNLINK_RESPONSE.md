# 회신 — DM 4기능 프로 전용 · 카카오 unlink (2026-10-15)

> `backend-dm-pro-kakao-2026-10-15.md` 에 대한 답입니다.

## 결론 먼저

| 요청 | 답 |
|---|---|
| 생성·수정·복제에 프로 게이트 | ✅ 넣습니다 |
| **재개(resume)에도 게이트** | ❌ **안 넣습니다** — 사장님 「유지」 결정과 모순됩니다(§1-2) |
| 비프로 사용 건수 | ✅ 아래 숫자. **베이직은 0명입니다**(§1-1) |
| `plans.features` 불리언 키 4개 | ✅ 넣습니다 |
| 탈퇴 시 카카오 unlink | ✅ 넣습니다. 어드민 키는 저희가 처리합니다 |
| 전화번호 「선택 동의」 유지 | ✅ 그대로 둡니다 |

🔴 **그리고 한 가지 — 카카오 `scope` 운영 배포를 unlink 까지 기다리실 필요가 없습니다.**
둘은 별개 문제입니다. 자세히는 §2-2 에 적었습니다.

## 1. DM 4기능 프로 전용

### 1-1. 베이직 사용자는 **0명**입니다

prod 실측(캠페인 2,629건, 플랜은 `workspace.owner` 구독 기준):

```
플랜 분포:  pro 2,352  /  free 276  /  admin 1      ← 베이직 0건
```

「베이직도 켤 수 있었다」는 전제는 맞지만, **실제로 켠 베이직 사용자가 없습니다.**
막게 될 대상은 전부 **free** — 체험이 끝나 무료로 떨어진 분들입니다.

| 기능 | 비프로 합계 | active | paused | inactive |
|---|---:|---:|---:|---:|
| `dm_follow_gate` | **41** | 13 | 18 | 10 |
| `dm_trigger_all_posts` | 4 | 3 | 1 | 0 |
| `dm_trigger_story_reply` | 1 | 1 | 0 | 0 |
| `dm_trigger_next_media` | **0** | 0 | 0 | 0 |
| **합계** | **46** | **17** | 19 | 10 |

참고로 프로까지 포함한 전체 사용량은 `follow_gate` 1,358 · `all_posts` 115 ·
`next_media` 30 · `story_reply` 1 입니다. `story_reply` 는 **전체에 1건뿐**이고 그 1건이
free 입니다.

→ 요금제 창에서 베이직 카드를 빼는 것은 그대로 가시면 됩니다. 다만 "베이직 사용자 구제"는
대상이 없으니 그쪽 분기에 공들이실 필요는 없습니다.

### 1-2. 재개(resume)는 막지 않습니다

요청에 **재개**가 들어 있었는데, 빼기로 했습니다(사장님 확인).

재개는 **값이 하나도 바뀌지 않는** 동작입니다 — 이미 저장돼 있던 자동화를 다시 켜는 것뿐입니다.
이걸 막으면 free 로 떨어진 **17건이 한 번 정지되는 순간 영구 봉인**됩니다. 그리고 정지는
사용자가 누르는 것만이 아닙니다:

- 게시물 연령제한 자동정지(`campaign_restriction` 스위퍼)
- DM 월 한도 소진
- 계정 단위 발송 차단(368) 복구 중

즉 **본인 의사와 무관하게 정지됐다가 재개를 못 하게 됩니다.** 「이미 돌고 있는 건 유지」라고
해놓고 실제로는 못 쓰게 되는 셈이라, 생성·복제만 막고 재개는 통과시킵니다.

**막는 것 / 안 막는 것**

| 동작 | 게이트 |
|---|---|
| 생성 (`POST`) | ✅ 막음 |
| **복제** | ✅ 막음 — 새 자동화라는 판단에 동의합니다 |
| 수정 (`PATCH`/`PUT`) | ✅ **새로 켜질 때만** 막음 |
| **재개** (resume · `status=active` 전이 · schedule activate) | ❌ 안 막음 |

「새로 켜질 때만」의 판정은 요청하신 그대로입니다 — **저장돼 있던 값과 비교**해서 꺼짐→켜짐일
때만 거절합니다. 같은 값을 그대로 다시 보내는 수정은 통과합니다. `follow_gate` 는
`follow_gate_enabled=true` **그리고** `gate_verify_follow=true` 조합이 새로 성립할 때만
걸립니다(버튼 링크 모드 `gate_verify_follow=false` 는 해당 없음 — 확인했습니다).

### 1-3. 거절 응답

```jsonc
HTTP 403
{
  "detail": "프로 요금제에서 사용할 수 있는 기능입니다.",
  "code": "PLAN_REQUIRED",
  "success": false,
  "error": {
    "code": 403,
    "message": "프로 요금제에서 사용할 수 있는 기능입니다.",
    "details": {
      "code": "plan_required",
      "required_plan": "pro",
      "feature": "dm_follow_gate"   // 걸린 기능 1개
    }
  }
}
```

요청하신 `error.details.code='plan_required'` · `required_plan='pro'` 그대로이고,
**어느 기능에서 걸렸는지** `feature` 를 같이 넣습니다(요금제 창 문구를 기능별로 쓰실 수 있게).
`detail`/`code` 를 envelope 과 **같이** 내보내는 건 이 저장소 규약입니다.

⚠️ 플랜 판정은 **`workspace.owner` 의 구독 기준**입니다(기존 게이팅과 동일). 멤버가 만들어도
워크스페이스 주인의 플랜을 봅니다.

### 1-4. `plans.features` 키

`GET /api/v1/billing/plans/` 의 `features` 에 넣습니다:

```jsonc
"dm_trigger_all_posts":   true/false,
"dm_trigger_next_media":  true/false,
"dm_trigger_story_reply": true/false,
"dm_follow_gate":         true/false
```

`pro`·`admin` 만 `true`, `free`·`basic` 은 `false`. 들어가면 플랜 **이름** 판정을 이 키로
바꿔 주세요. 넣는 즉시 알려 드리겠습니다.

## 2. 카카오

### 2-1. unlink — 넣습니다

코드에 `kapi.kakao.com/v1/user/unlink` 호출이 **한 줄도 없습니다.** 진단이 정확합니다.

- 어드민 키(`KAKAO_ADMIN_KEY`)가 운영에 없어서 **저희가 콘솔에서 발급해 넣습니다.**
- **탈퇴 경로가 2개라 둘 다** 넣습니다:
  `me/delete/`(즉시 하드삭제) · `deletion/*`(7일 유예 — `confirm_deletion`)
- IG 연동 해제와 같은 자리·같은 방식으로 붙입니다(트랜잭션 밖, 실패해도 탈퇴는 계속).
- **유예 중인 기존 탈퇴자는 일괄 unlink 가능합니다** — `confirm_deletion` 이 `kakao_id` 를
  지우지 않아 번호가 남아 있습니다. 다만 **이미 파기(purge)된 계정은 행이 없어 불가**합니다.

### 2-2. ⚠️ `scope` 운영 배포를 unlink 까지 미루지 마세요

**두 가지는 별개 문제입니다.**

| | 해결하는 것 |
|---|---|
| `scope=...phone_number` | **기존 연결자 818명 + 신규**에게 전화번호 동의 화면을 띄움 |
| unlink | **탈퇴했다가 다시 가입**하는 사람이 깨끗하게 재동의 |

사장님 계정에서 안 뜬 건 **dev 에서 이미 전화번호에 동의하셨기 때문**일 가능성이 큽니다
(회신에 그렇게 적어 주셨고, 카카오는 **이미 동의한 항목을 다시 묻지 않습니다**).
즉 **아직 동의한 적 없는 다른 카카오 계정에서는 `scope` 만으로 이미 뜰 것**입니다.

**검증은 이렇게 해 주세요** — 사장님 계정 말고, **전화번호에 동의한 적 없는 카카오 계정**으로
dev 로그인. 거기서 「카카오계정(전화번호) (선택)」이 뜨면 `scope` 는 완성입니다.

그게 확인되면 **운영에 먼저 올려 주세요.** 이건 **로그인할 때만** 받을 수 있어서, 배포가
하루 늦으면 그날 들어온 사람은 다음 로그인까지 기다려야 합니다. 지금 카카오 연결 818명 중
번호 보유는 40명뿐이고, 카카오로 받으면 **SMS 비용 0 · 사용자 입력 0회**입니다.

### 2-3. `scope` 에 닉네임·이메일을 같이 넣은 것 — 맞습니다

`scope=profile_nickname,account_email,phone_number` 그대로 두세요. 콘솔 설정이 닉네임·이메일
**필수 동의**라 빠지면 신규 가입이 깨질 수 있습니다. 백엔드가 `property_keys` 로 요청하는
세 항목과도 정확히 일치합니다.

### 2-4. 전화번호는 「선택 동의」 유지

콘솔에서 바꾸지 않습니다. 거부해도 로그인은 정상 완료되고, 그 경우 기존대로
`/signup/phone` 에서 직접 입력 + SMS 인증으로 받습니다. 받아온 번호는
**인증 완료로 간주**되어 `/signup/phone` 을 건너뜁니다(프론트 추가 작업 없음).

⚠️ **이미 번호가 있는 사용자는 덮어쓰지 않습니다** — 우리 SMS 로 인증한 번호가 우선입니다.

## 작업 순서

1. 카카오 어드민 키 발급 → 운영 투입 *(저희)*
2. unlink 2경로 + 유예 중 기존 탈퇴자 일괄 처리 *(저희)*
3. 4기능 플랜 게이트 + `plans.features` 키 *(저희)*
4. **그와 별개로 `scope` 운영 배포** *(프론트 — §2-2, 기다리실 필요 없습니다)*

1~3 끝나면 알려 드리겠습니다.

> ⚠️ **「사장님 계정으로 탈퇴 → 재가입해서 확인」은 안 하셔도 됩니다.**
> §2-2 대로 **전화번호 동의 이력이 없는 다른 카카오 계정**으로 dev 로그인하면 똑같이
> 판별됩니다. 그쪽이 빠르고, 되돌릴 것도 없습니다.
>
> unlink 검증이 꼭 필요하면 저희가 **테스트 계정**으로 돌려 보고 결과만 알려 드리겠습니다 —
> 실계정을 지웠다 만들 이유가 없습니다.
