## 왜 바뀌었나

이전 기능이 **게시물 100개까지만** 분석할 수 있었다. 게시물이 많은 계정에서는 실제 캠페인의
일부만 잡혀 "이전했는데 몇 개 안 나왔다" 가 됐다. 실측으로는 456개짜리 계정에서 313건이
복원 가능한데 배포본은 40건에서 멈췄다.

두 개의 벽이 있었고 둘 다 걷어냈다:
1. Graph 호출 예산이 게시물 수와 무관하게 고정 → 게시물 수에 비례하도록
2. 분석이 Celery 태스크 한도(25분)를 못 넘어 대형 계정은 **구조적으로 완주 불가**
   → 20분마다 진행분을 저장하고 이어서 실행하도록(이어달리기)

## 1. `media_limit` 상한 100 → **3000**

`POST /dm-migration/jobs/` 의 `media_limit` 최대값이 올라갔다. 기본값(50)은 그대로다.

프론트에서 "최근 N개 게시물 분석" 셀렉터를 100 까지만 노출하고 있다면 넓혀 주세요.
권장 프리셋: `50(빠름) / 200 / 500 / 전체`. "전체" 는 계정 게시물 수를 넣으면 된다
(모르면 1000 정도로 충분 — 없는 게시물은 그냥 안 잡힌다).

> 자동 선분석(연동 직후 백그라운드)은 이미 계정 게시물 수를 보고 자동으로 잡는다.
> 사용자가 나중에 이전 화면에 들어오면 캐시(7일)로 즉시 결과가 뜬다.

## 2. ⏱ 소요 시간 — **`estimate` 를 그대로 쓰세요** (하드코딩된 "10~20분" 폐기)

기존 문서의 "보통 10~20분" 은 100개 기준이었다. 이제 게시물 수에 비례한다.

| 게시물(댓글 있는 것) | 대략 |
|---|---|
| 50 | 5분 |
| 200 | 20분 |
| 500 | 50분 |
| 1000 | 100분 |

폴링 응답의 `estimate.seconds` / `estimate.seconds_max` 가 **서버가 계산한 실제 예상치**다
(1단계 끝나면 채워진다). 이 값으로 안내해 주세요.

> 배경에서 도는 작업이므로 사용자가 화면을 떠나도 계속 진행된다는 안내를 함께 주면 좋습니다.

## 3. ⚠️ `running` 이 **몇 시간** 지속될 수 있다 — 정체로 오판하지 마세요

대형 계정은 분석이 20분 단위로 잘려서 이어 달린다. 그 경계에서:

- `status` 는 계속 **`running`** (실패도, 일시정지도 아님)
- `message` 가 `"분석을 이어서 진행하고 있습니다..."` 로 바뀐다
- 다음 조각이 시작될 때까지 **약 75초 동안 `progress` 가 멈춰 보인다**

**"N초간 progress 가 안 오르면 실패로 간주" 같은 클라이언트 타임아웃이 있다면 제거하거나
최소 5분 이상으로** 잡아 주세요. 서버에는 이미 자체 감시가 있어서, 정말로 죽은 잡은
`failed` + `error.code="stalled"` 로 내려갑니다. **종결 상태로 내려오기 전까지는 살아 있는
것**으로 보시면 됩니다.

진행 표시는 `progress` 와 `message` 를 그대로 쓰면 됩니다. 별도 처리 필요 없습니다.

## 4. ⚠️ `resume_at` 으로 "일시정지" 를 판정하지 마세요

예전에는 `resume_at` 이 `paused_rate_limited` 일 때만 채워졌다. 이제 **`running` 상태에서도
채워진다**(다음 조각 예정 시각).

```diff
- if (job.resume_at) showPausedBanner()
+ if (job.status === "paused_rate_limited") showPausedBanner()
```

일시정지 배너는 **`status` 로만** 판정해 주세요. `resume_at` 은 "다음 갱신 예정 시각" 정도의
참고값입니다.

## 정리 — 프론트에서 할 일

| # | 할 일 | 필수 |
|---|---|---|
| 1 | `media_limit` 셀렉터 상한 확대 (100 → 최대 3000) | 권장 |
| 2 | 소요 시간 안내를 `estimate.seconds` 기반으로 | 권장 |
| 3 | progress 정체 기반 클라이언트 타임아웃 제거/완화 | **필수** |
| 4 | 일시정지 판정을 `status` 로만 (resume_at 사용 금지) | **필수** |

3·4번은 안 고치면 정상 동작 중인 대형 계정 분석이 화면에서 실패/일시정지로 보입니다.
1·2번은 안 고쳐도 오동작은 없습니다(기본값으로 동작).

응답 필드·엔드포인트·상태값은 **추가도 삭제도 없습니다.** 기존 연동은 그대로 동작합니다.
