## 1. DM-19 — `GET /admin/auto-dm/logs/{id}/` 에 `user_view` 추가

요청서의 구현 제안을 그대로 썼습니다. `build_frontend_action` 을 부르는 것이 전부입니다.

```jsonc
"user_view": {
  "user_reason": "ghost_opening_cleanup",
  "severity":    "info",     // success | info | warning | error
  "type":        "info",     // success | wait | reconnect | info | checklist
  "title":       "중복 발송을 방지했어요",
  "cause":       "이미 답장이 발송된 건이라, 같은 분께 두 번 발송되지 않도록 처리했어요.",
  "next_step":   "",
  "checklist":   null,       // 또는 [{id, title, description}, …]
  "cta":         null        // 또는 {label, action}
}
```

| 요청 | 반영 |
|---|---|
| 필드명 `user_view` | 그대로 |
| `description` 제외 | 제외 (8키만) |
| 상세 1건만 | 목록·수신자에는 넣지 않음 |
| 오류 아닌 상태에도 | delivered / read / queued 전부 채워짐 |

`error_*`(운영자 어휘)는 **그대로 있습니다.** `user_view` 는 덧붙인 것이지 대체가 아닙니다.

### 사본이 아니라 호출입니다 — 그리고 그걸 테스트가 지킵니다

요청서에서 가장 중요하게 짚으신 부분입니다. "조용히 틀린다"는 지적이 정확해서,
**말로 약속하지 않고 테스트로 고정**했습니다.

`tests_admin_19th_round.py` 13개가 막는 것:

| 무엇을 막나 | 어떻게 |
|---|---|
| 어드민 값 ≠ 고객 값 | 요청서가 든 4개 조합에 대해 유저 API 응답과 **8키 전부 대조** |
| 어딘가에 사본이 생김 | 문구 함수를 런타임에 갈아끼우고 **어드민 응답이 따라 바뀌는지** 확인 |
| 그릴 칸이 빔 | 키 셋 정확히 일치 + `description` 부재 |
| 목록에 새어 나감 | `/logs/` · `/recipients/` 에 `user_view` 없음 |

마지막 것은 요청하신 "목록에는 넣지 마세요"를 **지금 안 넣은 것**이 아니라
**앞으로도 안 들어가게** 만든 것입니다.

> 이 테스트들이 실제로 잡는지, 일부러 하드코딩 사본을 넣은 버전에 먼저 돌려서 확인했습니다
> (5건 실패 → 원복 후 13건 통과). 통과하는 테스트가 아무것도 검사하지 않는 경우를 몇 번
> 겪어서, 검출기는 고장난 버전에 먼저 돌려보고 있습니다.

## 2. 확인 요청 ① — 유저 콘솔 문구 덮어쓰기

### 지금 제거해도 됩니다. 오히려 **제거하는 게 맞습니다.**

읽으신 내용은 정확합니다. 다만 v4 배포(2026-08-07) 이후로 상황이 두 가지 달라졌습니다.

**첫째, 두 갈래 중 한 갈래는 이미 죽었습니다.**

그 우회는 조건이 둘입니다.

```ts
if (PRIVATE_REPLY_SUBCODES.has(subcode)) return true;          // ① subcode
return /private\s*reply/i.test(action.description || '');       // ② 설명 문자열
```

②는 서버 설명에 "Private Reply"가 들어 있을 때 걸리는 조건인데, **v4 문구 30벌 어디에도
그 단어가 없습니다**(코드에서 확인). 내부 용어를 걷어낸 게 이번 작업이었으니 당연한 결과입니다.
즉 지금 살아 있는 건 ①뿐입니다.

**둘째, 남은 ①도 서버와 고객 화면이 같은 말을 합니다.**

```
서버 (v4):     댓글을 삭제했거나 작성된 지 7일이 초과되었어요
유저 콘솔 우회: 메시지를 보내지 못했어요
               댓글을 삭제했거나 작성된 지 7일이 초과되었습니다.
```

문장 표현만 다르고 **말하는 사건이 같습니다.** 그 우회는 v3.2 시절 서버가
`Private Reply · ID · 파라미터 오류` 같은 내부 용어를 내려주던 것을 막으려고 만든 방어였는데,
서버가 제대로 말하게 되면서 **막을 것이 없어졌습니다.**

그래서 "어드민 미리보기가 거짓이 된다"는 우려는, 남은 범위에서는
**거짓이 아니라 표현 차이**입니다. CS 가 이 문구를 근거로 응대해도 고객과 어긋나지 않습니다.

### 노출량 — prod 실측

| subcode | 전체 로그 중 |
|---|---|
| `2534022` | **5건** |
| `2534015` | **0건** |
| 합계 | 5 / 42,491 = **0.01%** |

**어드민에서 별도 대응하실 필요 없다고 봅니다.** 두 subcode를 위해 예외 분기를 만드는 비용이
얻는 것보다 큽니다.

### 제거 시점

요청서에 적으신 UC 목록이 아직 유저 콘솔팀에 안 넘어간 게 아니라, **이미 UC-2로 요청돼
있습니다**(`docs/frontend/USER_CONSOLE_DM_COPY_REQUEST.md` §UC-2 "하드코딩 우회 제거").
서버 쪽 선행 작업은 v4 배포로 끝났고, 남은 건 프론트에서 그 6줄을 지우는 것뿐입니다.

어드민이 이 값을 쓰게 되면서 **UC-2의 우선순위가 올라갔다**는 점을 유저 콘솔팀에 전달하겠습니다.
제거되면 별도 공지드립니다.

## 3. 확인 요청 ② — `title`/`cause`/`next_step` 제거 계획

### 소비자에 어드민을 넣었습니다. 그리고 조건을 바꿨습니다.

지적하신 대로 §9의 제거 조건이 "프론트 이행 확인 후"였고, 여기서 프론트는 유저 콘솔만
가리켰습니다. **소비자가 둘이 됐으므로 조건을 고쳤습니다.**

바꾼 조건:

> 제거는 **유저 콘솔과 어드민 콘솔 양쪽이** `user_reason` 기준 렌더로 이행한 것을 확인한
> 뒤에만 한다. 한쪽만 이행한 상태에서 지우면 나머지 한쪽이 빈 칸이 된다.

그리고 제안하신 전환 방식 — **어드민이 유저 콘솔 i18n 사전을 참조**(복제가 아니라) —
이 맞다고 봅니다. 다만 그때 한 가지가 필요합니다.

- 유저 콘솔 i18n 이 **어드민에서 import 가능한 형태**여야 합니다. 지금은 유저 콘솔
  레포 안의 `src/locales/*/translation.json` 이라, 어드민이 가져다 쓰려면 별도 패키지든
  빌드 시 복사든 **경로가 하나 필요합니다.** 그 경로가 없으면 결국 복제로 돌아갑니다.
- 그 경로 설계는 두 프론트팀 사이의 문제라 저희가 정하지 않겠습니다. 다만 **제거를
  실행하기 전에 그게 정해져 있어야** 한다는 것을 §9 조건에 함께 적었습니다.

**당분간은 제거 계획이 없습니다.** 서버가 문장을 계속 채웁니다.
