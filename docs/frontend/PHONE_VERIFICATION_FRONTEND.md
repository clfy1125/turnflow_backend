# 휴대폰 본인확인 — 프론트엔드 연동 가이드

> **배경**: 카카오 알림톡으로 "체험 종료 · 결제 실패 · DM 발송 중단" 같은 **지금 알려야
> 손실을 막는** 알림을 보내려면 전화번호가 필요합니다. 2026-10-06 실측 기준 우리 DB 의
> 전화번호 보유는 **0건**이었습니다. 이 문서는 그 번호를 모으기 위한 백엔드 API 계약입니다.
>
> **작성** 2026-10-09 · **백엔드** 배포 대기 · 마이그레이션 `authentication 0010` · `sms 0001`
> **관련** [`KAKAO_LOGIN_FRONTEND.md`](KAKAO_LOGIN_FRONTEND.md) ·
> [`URGENT_CONVERSION_BACKEND_RESPONSE.md`](URGENT_CONVERSION_BACKEND_RESPONSE.md)

## 0. 세 줄 요약

1. **신규 가입자는 휴대폰 인증이 필수**입니다. 서버가 `phone_verification_required: true`
   로 알려주고, **차단은 프론트가** 합니다 (서버는 하드 차단하지 않습니다 — 아래 §2 이유).
2. **기존 회원은 선택**이고, 등록하면 **프로 체험 +7일**을 드립니다. 보상 금액·대상은
   서버가 계산해 내려주므로 프론트는 하드코딩하지 마세요.
3. 지금 배포해도 **아무 일도 일어나지 않습니다.** 필수화는 백엔드 환경변수
   (`PHONE_REQUIRED_SINCE`) 한 줄로 켜며, 그 전까지 모든 사용자에게 `required: false` 가
   내려갑니다. → **프론트 먼저 배포하고, 확인한 뒤 켜는** 순서입니다.

---

## 1. 배포 순서 — 이 순서를 지켜야 사고가 안 납니다

| # | 누가 | 무엇을 | 그 사이 사용자에게 보이는 것 |
|:-:|---|---|---|
| 1 | 백엔드 | API 배포 (`PHONE_REQUIRED_SINCE` **비움**) | 변화 없음. 모든 사용자 `required: false` |
| 2 | 프론트 | 화면 3종 배포 (§4) | 기존 회원에게만 "번호 등록 +7일" 팝업이 뜸. 신규 가입은 종전대로 |
| 3 | 백엔드 | `PHONE_REQUIRED_SINCE` 설정 | **이 시각 이후 가입자**부터 인증 화면 강제 |
| 4 | 운영 | 카카오 전화번호 동의항목 신청 | 승인되면 카카오 가입자는 문자 없이 번호가 채워짐 |

> ⚠️ **3번을 2번보다 먼저 하지 마세요.** 화면이 없는 상태에서 `required: true` 를 내리면
> 프론트는 그냥 무시하므로 장애는 없지만, "필수인데 아무도 안 한" 구간이 지표에 남습니다.
>
> ⚠️ **1번과 2번 사이는 안전합니다.** 새 필드는 전부 추가(additive)라 기존 화면이 깨지지
> 않습니다. `GET /auth/me/` 응답에 필드가 7개 늘어날 뿐입니다.

## 2. 서버는 왜 차단하지 않는가

`phone_verification_required: true` 는 **"지금 이 화면을 강제해야 한다"는 서버의 판정**이지
접근 차단이 아닙니다. 서버가 미인증 사용자의 API 를 전부 막으면:

- 프론트 배포가 하루만 늦어도 **전 신규 가입자가 서비스에 못 들어옵니다**
- 네이티브 앱은 스토어 심사 때문에 웹과 동시에 배포할 수 없습니다

대신 **판정은 서버가 독점**합니다. 프론트가 `date_joined` 로 "이 사람은 신규인가"를
직접 계산하지 마세요 — 정책이 바뀌면 서버만 바꾸면 되도록 설계했습니다
(`conversion_consent_required` 와 같은 규약).

## 3. API 계약

Base: `https://api.turnflow.link/api/v1` (dev: `https://dev-api.turnflow.link/api/v1`)
전부 `Authorization: Bearer <access_token>` 필요.

### 3-1. `GET /auth/me/phone/` — 상태 조회 (부작용 없음)

팝업을 띄울지, 보상 문구를 뭐라고 쓸지 판단할 때 **자유롭게** 호출하세요. 문자를 보내지
않습니다.

```json
{
  "phone": "010-1234-5678",
  "phone_verified": true,
  "phone_source": "sms",
  "required": false,
  "sms_marketing_opt_in": false,
  "resend_after": 0,
  "daily_remaining": 5,
  "reward": { "kind": "trial_extended", "days": 7, "reason": "", "trial_ends_at": "2026-11-16T00:00:00+09:00" }
}
```

| 필드 | 뜻 |
|---|---|
| `phone` | 등록된 번호(하이픈 표기). 미등록이면 `""` |
| `phone_verified` | 본인확인 완료 여부 |
| `phone_source` | `sms`(우리 문자 인증) / `kakao`(카카오 동의항목) / `""` |
| `required` | 지금 인증 화면을 강제해야 하는가 |
| `resend_after` | 지금 발송 요청하면 몇 초 뒤 가능한가. **새로고침 후 카운트다운 복원에 쓰세요** |
| `daily_remaining` | 이 번호로 오늘 남은 발송 횟수 |
| `reward` | 지금 등록하면 받는 보상 **예고**. §3-4 |

### 3-2. `POST /auth/me/phone/` — 인증번호 발송

```jsonc
// 요청
{ "phone": "010-1234-5678" }   // 하이픈/공백/+82 모두 허용. 서버가 정규화합니다
```
```jsonc
// 202
{
  "detail": "인증번호를 보냈습니다.",
  "phone_masked": "010-****-5678",
  "expires_in": 180,        // 초 — 입력 화면 타이머
  "resend_after": 60,       // 초 — 재발송 버튼 비활성 시간
  "daily_remaining": 4,
  "reward": { "kind": "trial_extended", "days": 7, "reason": "", "trial_ends_at": "..." }
}
```

### 3-3. `POST /auth/me/phone/verify/` — 인증번호 확인

```jsonc
// 요청
{ "code": "123456", "sms_marketing_opt_in": false }   // opt_in 은 선택, 기본 false
```
```jsonc
// 200
{
  "detail": "휴대폰 인증이 완료되었습니다.",
  "user": { /* GET /auth/me/ 와 같은 전체 프로필 */ },
  "reward": { "kind": "trial_extended", "days": 7, "reason": "", "trial_ends_at": "2026-11-16T00:00:00+09:00" }
}
```

### 3-4. `reward` 객체 — 보상은 서버가 계산합니다

| `kind` | 화면 문구 | 언제 |
|---|---|---|
| `trial_extended` | "프로 체험이 **{days}일** 늘었어요" | 체험 중인 기존 회원 |
| `trial_granted` | "프로 체험 **{days}일**이 시작됐어요" | 체험을 아직 안 쓴 기존 회원 (30일) |
| `paid_extended` | "다음 결제일이 **{days}일** 미뤄졌어요" | 유료 구독자 (기본 비활성) |
| `none` | **보상 문구를 숨기세요** | `reason` 참조 |

`reason` (kind 가 `none` 일 때):
`new_signup`(인증이 필수인 신규 가입자 — 애초에 보상 대상 아님) · `already_granted`(이미 받음) ·
`phone_already_rewarded`(같은 번호로 이미 나감) · `not_eligible`(지급 가능한 구독 상태 아님) ·
`disabled`(기능 OFF)

> ⚠️ **`days` 를 7 로 하드코딩하지 마세요.** 환경변수로 바꿀 수 있고, `trial_granted` 는
> 30일입니다. **`kind === "none"` 인데 보상 문구를 띄우면 그대로 허위 고지**입니다.
>
> ✅ 발송 응답(`3-2`)의 `reward` 와 확인 응답(`3-3`)의 `reward` 는 **같은 판정 함수**를
> 쓰므로 어긋나지 않습니다. 입력 화면에서 미리 보여줘도 안전합니다.

### 3-5. `DELETE /auth/me/phone/` — 번호 삭제

개인정보 자기결정권(개인정보보호법 §37) — 탈퇴하지 않고도 번호를 뺄 수 있어야 합니다.
인증이 **필수인 계정**은 409 `PHONE_REQUIRED` 로 거부됩니다(번호를 바꾸려면 삭제가 아니라
새 번호로 다시 인증 → 덮어쓰기).

확인 모달에 꼭 넣어 주세요: *"삭제하면 체험 종료·결제 실패 알림을 카카오톡으로 받지 못합니다."*

## 4. 화면 3종

### 4-1. 신규 가입 — 필수 단계 `/signup/phone`

가입(이메일·구글·카카오·인스타) 직후, `required === true` 인 동안 **벗어날 수 없는** 화면.

```
┌──────────────────────────────────────┐
│  휴대폰 번호를 입력해 주세요            │
│  중요한 알림을 카카오톡으로 보내드려요   │
│                                      │
│  [ 010-1234-5678        ]  [인증번호 받기] │
│  [ 000000 ]  02:47 남음     [재발송(47)]  │
│                                      │
│  □ (선택) 혜택·프로모션 정보 수신 동의    │
│                          [ 확인 ]      │
└──────────────────────────────────────┘
```

> 🔑 **이 화면의 URL 과 캡처를 카카오 동의항목 심사에 제출합니다.** 카카오는 "실제
> 회원가입 페이지에서 전화번호를 수집하는 경우만" 전화번호 동의항목을 승인합니다.
> 그래서 경로를 `/settings/...` 가 아니라 **`/signup/phone`** 으로 두고, 화면 제목에도
> "회원가입" 맥락이 보이게 해 주세요.

**라우팅 가드**: `required === true` && 현재 경로 ≠ `/signup/phone` → 리다이렉트.
`required` 는 `GET /auth/me/` 와 `GET /auth/me/phone/` 둘 다에 있습니다.

### 4-2. 기존 회원 — 보상 팝업

```
┌────────────────────────────────────────┐
│  📱 휴대폰 등록하고 프로 체험 7일 더 받기 │
│                                        │
│  인스타 연결이 끊기거나 체험이 끝나기 전   │
│  카카오톡으로 바로 알려드려요.            │
│                                        │
│     [ 나중에 하기 ]   [ 등록하고 받기 ]   │
└────────────────────────────────────────┘
```

**노출 조건** (전부 서버 값으로 판단):
```ts
const s = await getPhoneStatus();           // GET /auth/me/phone/
const show = !s.phone_verified && !s.required && s.reward.kind !== 'none';
```

**노출 빈도**는 기존 `popup_state`(`GET/PATCH /auth/me/popup-state/`)를 재사용하세요 —
기기 간 동기화됩니다. 제안 키: `phone_collect`, 규칙 `최대 3회 · 닫으면 7일 뒤 재노출 ·
등록 완료 시 영구 중단(converted)`.

> ℹ️ 인앱 팝업이 **주력 채널**입니다. 이메일 캠페인은 광고 수신동의자 174명(6.6%)에게만
> 보낼 수 있어(정보통신망법 §50) 보조입니다. 백엔드에 메일 발송 배치가 있지만 **기본
> 꺼져 있습니다**.

### 4-3. 설정 — 내 정보

- 미등록: "휴대폰 등록" 버튼 → 같은 입력 컴포넌트
- 등록됨: `010-****-5678` 표기 + "변경"(새 번호 인증) / "삭제"(§3-5)
- 광고 수신동의 토글: `PATCH /auth/me/ { "sms_marketing_opt_in": true|false }`

## 5. 에러 코드 — **절대 generic 문구로 뭉개지 마세요**

> ⚠️ 이 프로젝트는 같은 실수를 **두 번** 겪었습니다. 추가 IG 계정 견적의 `QuoteGate` 가
> 400 사유를 버리고 "잠시 후 다시 시도"로 뭉개서 고객이 3분간 8회 재시도했고
> (CS #d34572b3), 탈퇴 모달도 401 외 전부를 generic 으로 덮어 백엔드가 보낸 사유가
> 화면에 닿지 못했습니다(CS #247995c5). **여기서 반복하면 "인증번호가 안 와요" CS 가
> 원인 불명으로 쌓입니다.**

모든 오류 응답은 `detail`(사람이 읽을 문구) + `code`(머신 키) + §6 envelope 을 **동시에**
냅니다. 분기는 `code` 로, 표시는 `detail` 로 하면 서버 문구 수정이 프론트 배포 없이 반영됩니다.

### 발송 `POST /auth/me/phone/`

| HTTP | `code` | 화면 처리 |
|:-:|---|---|
| 400 | `PHONE_INVALID` | 입력란 아래 `detail` 표시. 재입력 유도 |
| 400 | `PHONE_ALREADY_VERIFIED` | "이미 등록된 번호예요" — 다른 번호 입력 유도 |
| 429 | `PHONE_RESEND_TOO_SOON` | **`retry_after` 초 카운트다운**. 토스트 금지(버튼을 비활성화) |
| 429 | `PHONE_DAILY_LIMIT` | "오늘은 더 받을 수 없어요. 내일 다시 시도하거나 고객센터로 문의" + 문의 버튼 |
| 429 | `PHONE_IP_LIMIT` | `detail` 그대로 + 잠시 후 재시도 |
| 429 | (throttle, `code` 없음) | 사용자당 5회/시간. "잠시 후 다시 시도" |
| 502 | `SMS_SEND_FAILED` · `SMS_UNAVAILABLE` | **재시도 버튼 제공** (일시 장애) |
| 503 | `SMS_CAPACITY_EXCEEDED` | 운영 사고. "일시적으로 보낼 수 없어요" + 고객센터 |

### 확인 `POST /auth/me/phone/verify/`

| HTTP | `code` | 화면 처리 |
|:-:|---|---|
| 400 | `PHONE_CODE_INVALID` | **`attempts_left` 회 남음** 표시. 0 이면 재발송 버튼으로 전환 |
| 400 | `PHONE_CODE_EXPIRED` | "만료됐어요. 다시 받아주세요" → 재발송 |
| 400 | `NO_PENDING_PHONE_VERIFICATION` | 발송 단계로 되돌리기 |
| 429 | (throttle) | 10회/분 |

```ts
// 권장 처리 패턴
const res = await fetch(url, opts);
if (!res.ok) {
  const e = await res.json().catch(() => ({}));
  switch (e.code) {
    case 'PHONE_RESEND_TOO_SOON': return startCountdown(e.retry_after);
    case 'PHONE_CODE_INVALID':    return setHint(`${e.attempts_left}회 남았습니다`);
    default:                      return setError(e.detail ?? '잠시 후 다시 시도해 주세요.');
    //                                              ^^^^^^^ 반드시 detail 을 먼저 쓸 것
  }
}
```

## 6. `GET /auth/me/` 변경 — 추가 7필드 (전부 additive)

```jsonc
{
  // ... 기존 필드 그대로 ...
  "phone": "010-1234-5678",              // 미등록 ""
  "phone_verified": true,
  "phone_verified_at": "2026-10-09T12:00:00+09:00",
  "phone_verification_required": false,  // ⭐ 라우팅 가드는 이 값으로
  "sms_marketing_opt_in": false,
  "sms_marketing_opt_in_at": null
}
```

`PATCH /auth/me/` 로 바꿀 수 있는 것은 **`sms_marketing_opt_in` 하나**입니다
(번호 자체는 본인확인을 거쳐야 하므로 read-only).

## 7. 동의 문구 — 법무 요구사항

### 7-1. 휴대폰 번호 수집 (필수)

가입 화면에 아래가 **보여야** 합니다(링크 아님, 본문 노출 권장):

> **[필수] 휴대폰 번호 수집·이용 동의**
> · 수집 항목: 휴대폰 번호
> · 이용 목적: 본인확인, 서비스 중요 알림(체험 종료·결제·연동 상태) 발송
> · 보유 기간: 회원 탈퇴 시까지 (관계 법령에 따른 보존 제외)
> · 동의를 거부할 수 있으나, 거부 시 회원가입이 제한됩니다.

마지막 줄이 **필수 수집의 법정 고지**입니다(개인정보보호법 §22의2). 빠뜨리지 마세요.

### 7-2. 광고성 정보 수신 (선택)

> ☐ **(선택)** 혜택·이벤트 등 광고성 정보 수신에 동의합니다. (문자·카카오 알림톡)
> 미동의 시에도 체험 종료·결제 안내 등 **서비스 필수 알림은 발송**됩니다.

- **기본 미체크**여야 합니다 (사전 동의 원칙).
- "(선택)" 표기는 **필수**입니다.
- ⚠️ 기존 `marketing_opt_in`(이메일)과 **별개 필드**입니다. 정보통신망법 §50 은 전송
  **매체별** 동의를 요구하므로, 메일 동의로 알림톡을 보낼 수 없습니다.

## 8. 카카오 로그인 — 바뀌는 것

운영팀이 카카오 개발자센터에서 **`카카오계정(전화번호)` 동의항목**을 승인받으면:

- **신규 카카오 가입자**: 가입과 동시에 번호가 채워집니다 → `required: false`,
  **휴대폰 인증 화면을 건너뜁니다**. (프론트는 `required` 만 보면 되므로 별도 분기 불필요)
- **기존 카카오 회원**: 카카오 "추가 항목 동의 받기"로 **다음 로그인 때** 동의를 받으면
  그 순간 번호가 채워집니다. 문자 한 통도 쓰지 않습니다.
- `phone_source` 가 `"kakao"` 로 내려옵니다. 설정 화면에서 "카카오계정에서 가져온 번호"
  라고 표기해 주면 사용자가 덜 당황합니다.

> ⚠️ 승인 전까지는 동의항목이 없어 번호가 오지 않습니다 — 그때는 카카오 가입자도
> 문자 인증을 거칩니다. **프론트는 양쪽 모두 `required` 값만 보면 되므로 분기가
> 필요 없습니다.**
>
> ⚠️ 이미 우리 문자로 인증한 번호가 있으면 카카오 번호로 **덮어쓰지 않습니다**
> (사용자가 실제로 쓰는 번호가 더 정확할 수 있어서).

## 9. dev 에서 테스트하기

dev 서버는 `SMS_MOCK_MODE=True` 라 **문자가 실제로 가지 않습니다.**

- 발송 API 는 정상적으로 202 를 돌려줍니다 (화면 플로우 검증 가능)
- 인증번호는 백엔드 로그(`aligo[mock]`)에도 **찍히지 않습니다**(평문 금지)
- 👉 dev 에서 끝까지 통과해야 한다면 백엔드에 요청하세요 — 특정 계정의 코드를
  꺼내 드립니다. 또는 실제 번호로 테스트할 수 있게 dev 를 잠시 실발송으로 전환합니다.

`010-0000-0000` 같은 고정 테스트 번호는 **만들지 않았습니다** — 그 우회로가 운영에
섞여 들어가면 아무나 그 번호로 계정을 인증할 수 있게 됩니다.

## 11. 백엔드가 걸어둔 안전장치 (참고)

문자는 **건당 돈이 나가고**, 봇이 인증 요청을 쏟아부어 잔액을 태우는 공격(SMS 펌핑)이
실재합니다. 네 겹으로 막습니다 — 프론트에서 추가로 막을 필요는 없지만, 왜 429 가
나오는지 알고 있어야 안내 문구를 제대로 쓸 수 있습니다.

| 겹 | 제한 | 막는 것 |
|---|---|---|
| DRF 스로틀 | 사용자당 5회/시간 | 한 계정의 연타 |
| 번호별 쿨다운 | 60초 | 재발송 버튼 난타 |
| 번호별 일일 | 5회 | **한 번호에 쏟아붓기** (실질 방어선) |
| IP 일일 | 100회 | 번호 돌려막기 (CGNAT 고려해 느슨) |
| 전역 일일 | 2,000건 | 위가 전부 뚫렸을 때의 **금액 상한** |

그 밖에:
- 국내 휴대폰(010/011/016~019)만 허용 — 해외번호 거부로 SMS 펌핑 수익 구조가 끊깁니다
- 인증번호는 **평문 저장 안 함**(HMAC-SHA256) · 3분 만료 · 5회 시도 · 1회용
- 익명 발송 경로 **없음**(로그인 필수) — 공격자가 먼저 계정을 만들어야 하고 가입도 제한됨
