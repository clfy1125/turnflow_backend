# 카카오 로그인 URL 에 `scope=phone_number` 추가 요청 (⏩ 빠른 배포 권장)

> **작성** 2026-10-15 · **백엔드 작업 없음**(이미 받을 준비 완료) · **프론트 1줄**

## 요청

카카오 authorize URL 에 `scope=phone_number` 를 추가해 주세요.

```diff
  https://kauth.kakao.com/oauth/authorize
    ?client_id={REST_API_KEY}
    &redirect_uri={REDIRECT_URI}
    &response_type=code
+   &scope=phone_number
```

이게 전부입니다. 백엔드는 번호가 오면 저장하는 코드가 **이미 배포돼 있습니다**(`kakao.py` ·
`kakao_views.py`). 받아서 `phone_verified` 까지 찍습니다.

---

## 왜 필요한가

카카오 「카카오계정(전화번호)」 동의항목이 **2026-10-14 심사 승인 → 선택 동의로 활성화**됐습니다.
그런데 **아무에게도 안 뜹니다.**

- 카카오는 **이미 연결된 계정**에게 새로 추가된 선택 항목을 **자동으로 다시 묻지 않습니다.**
  이미 동의한 항목(닉네임·이메일)만으로 로그인이 되니 동의 화면 자체를 건너뜁니다.
- 동의 화면에 항목을 **띄우는 건 authorize 의 `scope`** 입니다.
  (백엔드의 `property_keys` 는 프로필 *조회* 시 받을 필드 지정일 뿐 — 화면을 못 띄웁니다)

실측: 사장님 카카오 계정으로 로그인해 봤는데 전화번호 체크박스가 **안 떴습니다.**

## 왜 빨리 올리면 좋은가

| | 숫자 |
|---|---|
| 카카오 연결 계정 | **818명** |
| 그중 번호 보유 | 40명 |
| `phone_source=kakao` (카카오가 준 번호) | **0** |
| `phone_source=sms` (우리가 문자 쏴서 받은 번호) | 126 |

**1. 문자 비용이 0 이 됩니다.** 지금은 번호 하나 받으려고 SMS 를 건당 돈 내고 쏩니다.
카카오에서 받으면 **발송 0건**이고, 받는 즉시 인증 완료로 처리돼 `/signup/phone` 단계도
건너뜁니다(사용자 입력 0회).

**2. 늦어질수록 기회가 날아갑니다.** 이건 **사용자가 로그인할 때만** 받을 수 있습니다.
오늘 배포가 늦으면 오늘 로그인한 사람은 다음 로그인까지 기다려야 합니다. 818명이
한 번씩 들어오는 데 걸리는 시간만큼 수확이 밀립니다.

**3. 지금 모든 선행조건이 끝나 있습니다.** 심사 승인 ✅ · 동의항목 활성화 ✅ ·
백엔드 수신 코드 ✅ · 처리방침 기재 ✅. **프론트 1줄만 남았습니다.**

## 붙이는 방식 — 셋 중 하나

| | 방식 | 평가 |
|---|---|---|
| **A** | 카카오 로그인 버튼에 **항상** `scope=phone_number` | **지금 추천.** 1줄이라 오늘 올릴 수 있습니다. 카카오는 **한 번 동의한 항목은 다시 안 묻습니다** → 동의한 사람은 1회만 보고 끝. 단 **거부한 사람은 로그인할 때마다 다시 봅니다** |
| **B** | 번호 없는 사람에게만 | 로그인 **전**이라 프론트가 `phone_verified` 를 모릅니다 → 그대로는 불가 |
| **C** | 신규 가입 버튼에만 붙이고, 기존 회원은 설정/배너에서 「카카오에서 번호 가져오기」로 유도 | 가장 깔끔. 작업량이 있어 2차로 |

**제안: 지금 A 로 올리고, 거부자 반복 노출이 거슬리면 C 로 다듬기.**

## 참고 — 안 바뀌는 것

- **백엔드 API 변경 없음.** 응답 필드·에러 코드 그대로입니다.
- **거부해도 로그인은 정상입니다**(선택 동의). 그 경우 기존대로 `/signup/phone` 에서
  직접 입력 + SMS 인증으로 받습니다.
- **이미 번호가 있는 사람은 덮어쓰지 않습니다** — 우리 SMS 로 인증한 번호가 우선입니다
  (`kakao_views.py`: 번호가 **비어 있을 때만** 채웁니다).
