DM 캠페인 이전 — 2차 연구
"복원 불가"는 사실이 아니었다

1차 연구노트가 "바이럴 게시물은 원천적으로 복원 불가"라고 결론 낸 게시물들을, 조건 하나만 바꿔 전부 복원했습니다.

2026-08-13 · 실서버 읽기 전용(GET) 조회로 검증 · 정답지 = 우리 SentDMLog 53,228건

한 줄 결론

DM은 처음부터 거기 있었습니다. 우리가 봉투를 안 열어봤을 뿐입니다.

DM 자동화 도구는 버튼이 달린 DM을 보냅니다. 그런 DM은 본문이 message 필드에 없고 attachments 안에 들어갑니다. 우리 수집기는 message 만 요청했기 때문에, 화면에는 멀쩡히 보이는 DM이 API 응답에서는 빈 문자열로 왔습니다.

"전달이 안 됐다"가 아니라 "우리가 안 읽었다" 였습니다.

1. 무슨 일이 있었나 — 그림으로

지금까지  fields=...,message

DM을 달라고 했더니 봉투만 왔습니다. 발신인·시각·ID는 다 맞는데 내용물 칸이 비어 있습니다. 파이프라인은 이걸 "보낸 DM이 없다"로 읽었습니다.

"id": "...723020", "from": { "id": "17841433664113547" }, "created_time": "2026-08-13T10:30:06+0000", "message": "" ← 비어 있음

고치면  fields=...,message,attachments

같은 메시지에 attachments 만 추가했더니 본문·버튼 문구·오퍼 링크가 통째로 나옵니다. 1차 연구가 못 찾던 게 여기 다 있었습니다.

"attachments": { "data": [ { "generic_template": { "title": "DM 본문 전체", "cta": [ { "title": "버튼 문구", "url": "오퍼 링크", "type": "web_url" } ] } } ] }

왜 아무도 몰랐나 — 사람 눈에는 DM이 정상으로 보이고, API도 200 OK 를 주고, 메시지 ID까지 정확히 일치합니다. "내용만 빈 문자열"이라 실패로 보이지 않고 "그런 DM이 없었다"로 보입니다. 1차 연구는 이 침묵을 "전달 실패"로 해석했고, 그 위에 "비팔로워라 채널이 안 열렸다"는 그럴듯한 인과를 얹었습니다.

3. 가설 판정표 — 1차 연구의 결론을 하나씩

1차 연구의 주장판정근거
바이럴 게시물은 비팔로워라 DM이 전달 자체가 안 됐다 기각 같은 게시물에서 314건 복원됨. 전달은 됐고 읽히지도 않았을 뿐
대화가 없으니 정렬·깊이와 무관하게 복원 불가 기각 대화는 존재. 조회한 36명 중 35명(97%)이 DM 보유
수락 안 된 요청은 API가 안 보여준다 (2차 연구가 세운 경쟁 가설) 기각 미열람(delivered·읽음 없음) 수신자 36명 전원 대화 반환 100%
댓글 정렬이 복원율 최대 레버 — tail 38% vs 최신 1.7% (22배) 아티팩트 의심 첨부를 읽으면 tail 표본 적중률이 97% 로 포화. 22배 격차는 "텍스트 DM만 세던" 조건에서 생긴 왜곡일 가능성이 크다 — 재검증 필요
댓글러당 발신 DM 적중률 ~6% 라 표본을 키워야 한다 기각 실측 97~100%. 6%는 "첨부 DM을 못 본" 상태의 수치였다
깊은 페이징으로도 못 살리니 캡을 올리는 건 API 낭비 결론은 유지, 이유는 정반대 캡을 올릴 필요가 없는 건 맞다. 단 "복원이 불가능해서"가 아니라 얕게 떠도 거의 다 맞아서
팔로우게이트·버튼 구조는 복원 불가 (기존 문서 §8) 기각 첨부에 버튼 문구·URL·게이트 문구가 그대로 들어 있다 → 캠페인 구조까지 복원 가능

2차 연구가 중간에 틀렸던 것도 기록해 둡니다. 첨부를 발견하기 전, 저는 "공개답글 parent_id 로 트리거 확정자를 뽑는 정밀 타게팅"이 가장 큰 레버라고 추정했습니다(확정자의 93%를 한 번도 조회 안 하고 있었으므로). 측정해 보니 틀렸습니다 — 첨부를 읽는 순간 기존 tail 표본도 97%를 맞히기 때문에, 정밀 타게팅의 추가 이득은 97%→100% 로 미미합니다. 병목은 표본이 아니라 필드였습니다.

4. 부수 소득 — 첨부를 읽으면 덤으로 따라오는 것

얻는 것어디서효과
오퍼 링크(URL)cta[].url 복원 DM의 43%(110/253)가 URL 보유 → 판정식상 Tier 1(auto_draft) 자동 승격
버튼 문구cta[].title초안 CTA를 지어내지 않고 실제 문구를 쓸 수 있다
팔로우게이트 유무게이트 템플릿이 별도 첨부로 존재 기존 문서 §8이 "복원 불가"로 적은 항목 — 캠페인 구조 복원이 가능해진다
2단 DM(리워드) 구조같은 대화의 첨부 2건오프닝 → 리워드 흐름을 관측으로 재구성

5. 고쳐야 할 곳

  1. 수집 필드에 attachments 추가 — apps/integrations/services.py 의 list_user_conversation() · list_conversations() 두 곳. 영향 최대 한 줄
  2. 본문 추출 함수 신설 — message 가 비면 attachments[].generic_template.title + cta[].title/url 을 조립. 수집기(collect.py)의 발신 DM 파싱 2곳이 함께 쓰게 할 것 (규칙 복제 금지 — 단일 소스)
  3. is_noise_dm() 재검토 — "팔로우 확인을 위해 아래 버튼을 눌러주세요" 같은 게이트 문구는 노이즈가 아니라 구조 신호다. 현재 규칙은 URL이 붙어야 살아남는다. 첨부에서 조립하면 URL이 함께 오므로 대체로 통과하지만, 게이트 전용 템플릿은 별도 분류가 낫다
  4. 복원 DM을 군집 풀에 합류 — pipeline.py _stage_cluster 가 전역 스캔분만 군집화한다. 실측: 전역만 템플릿 1개 → 복원분 합치면 4개(최상위 지지도 8→40). 게시물 매칭에 실패한 건이 "실제로 보낸 문구"에 붙을 수 있게 된다
  5. excluded 재분류 — 공개답글이 있는 게시물은 캠페인이 돈 물증이 있는 것이다. "캠페인 없음"이 아니라 "본문 미상"으로 needs_review 노출
  6. 예산 캡 재산정 — 적중률이 6%가 아니라 97%라면 comments_oldest(400) 깊은 페이징의 근거가 사라진다. 줄일 수 있는지 재검증 → API 비용 하락 여지

6. 그래도 남는 진짜 한계

이번 발견으로도 안 되는 건 정직하게 남깁니다.

  • 대화당 최근 ~25건 제한 — 그 뒤로 대화가 길어진 상대의 오래된 캠페인 DM은 밀려나 안 보인다
  • 정말로 전달 실패한 건(채널 미개설 2534025) — 실측에서 이 버킷은 대화 반환률 50% 로 절반이 실제로 비어 있었다. 즉 1차 연구의 "미전달" 가설이 완전히 틀린 건 아니고, 다만 그게 바이럴 게시물 복원 실패의 주원인은 아니었다
  • 후속 시퀀스 분기 로직 — 조건/딜레이는 발신 기록만으로는 복원 불가(문구는 복원 가능)
  • 최후의 수단은 여전히 유효 — "이 게시물의 DM 문구를 붙여넣으세요" 입력창. 100% 자동일 필요는 없다

7. 방법론 교훈

정답지가 있는 데이터로 먼저 돌렸으면 즉시 잡혔다. 우리는 SentDMLog 에 "누구에게 무슨 문구를 보냈는지" 53,228건을 갖고 있습니다. 그 중 아무거나 하나 골라 "우리가 보낸 이 DM이 조회에 잡히나?" 를 물었으면 0% 매칭이 바로 나왔을 겁니다.

1차 연구는 정답을 모르는 외부 계정에서 시작해, 안 나오는 이유를 추론으로 메웠습니다. 그 추론(비팔로워 미전달)은 그럴듯했고, 데이터와도 모순되지 않았고, 틀렸습니다.

→ 규칙: 탐지기·수집기는 결과를 아는 데이터에 먼저 돌려 교정하고, 그다음에 미지 데이터로 나간다.

검증 방식: prod 읽기 전용(GET) — DB 조회 + Graph API GET 만 사용, 쓰기·발송 없음. 실험 스크립트는 세션 스크래치패드에 보관(probe1~probe7).
