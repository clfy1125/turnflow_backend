DM 캠페인 이전 — 무엇이 '진짜 복원'이고 무엇이 '추정'인가

타 DM 자동화 툴(매니챗·인포크링크 등) 사용자의 기존 캠페인을 IG 공개·메시징 데이터로 되살리는 파이프라인의 동작 설명서. 소스: apps/integrations/dm_migration/ · 실데이터 검증: RESEARCH_NOTE.md

결론부터. "100% 이전"에 해당하는 건 실제로 발송된 DM 원문을 그 게시물에 직접 연결해 복원한 경우뿐이고, 파이프라인은 그걸 dm_source = "targeted" 로 표시한다. 나머지는 전부 정황 추정이다.

구분 축은 밴드(band)가 아니라 evidence_aggregates.dm_source 다. 같은 auto_draft 밴드 안에도 "실제 DM 복원"과 "시간·볼륨 상관으로 추정"이 섞여 있어서, 밴드만 보면 신뢰도를 구분할 수 없다. 실측(mini_ai_ 계정)에서는 후보 31개 중 28개가 실제 복원 기반이었다.

1. 신뢰 등급 5단계 — 판정식과 초안 출처

TIER 1 · 진짜 복원 dm_source=targeted · band auto_draft

그 게시물에 댓글을 단 사람의 DM 방을 직접 열어, 계정이 실제로 보낸 DM 본문을 꺼내왔다. 게시물↔DM 링크가 추론이 아니라 관측이다.

승격 조건
has_url(링크 페이로드 포함) 또는 recipients ≥ 2(동일 문구를 2명 이상에게) → 자동화 템플릿 확정
점수
final_score = 0.90 (고정 — 관측이므로 상관점수를 계산하지 않는다)
첫 DM 초안
복원된 실제 문구가 LLM 입력(template_text)으로 들어가 다듬어진다
근거 원본
evidence_raw.sample_outbound_dms = 실제 발신 DM 최대 3건(원문·발송시각)
프론트 표기
"실제 발송 DM N건에서 복원" — 수신자 수(dm_recovered_recipients) 함께 노출

단, 이것도 "캠페인 전체"가 아니라 오프닝 DM + 트리거 키워드 + 공개답글까지다. §8 참조.

TIER 2 · 복원했지만 약함 dm_source=targeted_weak · band needs_review

DM 을 복원하긴 했는데 수신자 1명 · 링크 없음 → 자동화 템플릿이 아니라 수동 1회성 답장일 수 있다.

점수
final_score = 0.55 (고정)
첫 DM 초안
복원 원문을 LLM 에 넣지 않는다 (template_text="") — 사적 대화 1건을 템플릿처럼 일반화하면 환각이 난다. 초안은 캡션·키워드만으로 생성
근거 원본
복원 원문은 evidence_raw 에 보존해 사람이 직접 보고 판단하게 한다

"복원 성공 ≠ 자동으로 초안 재료"인 유일한 등급. 관측은 있으나 일반화를 유보하는 지점.

TIER 3 · 정황 추정 dm_source=global · band auto_draft 또는 needs_review

게시물↔DM 직접 링크가 없다. 계정 전체 대화방을 스캔해 만든 반복 템플릿 목록에서, 시간·볼륨·키워드 상관으로 "이 게시물엔 이 템플릿이었을 것"이라고 고른 것.

점수식
python_score = 0.5·time + 0.3·volume + 0.2·keyword_in_template
time = 0.5·(댓글날짜 ∩ 발송날짜 Jaccard) + 0.5·(게시 후 30일 내 발송 비중)
AI 보정
0.35 ≤ python_score ≤ 0.75 구간만 LLM 적합도 판정 → final = 0.6·python + 0.4·fit
밴드 컷
final ≥ 0.70 && 분류신뢰도 ≥ 0.70 → auto_draft / final ≥ 0.45 → needs_review / 그 미만 → excluded
주의
여기서 나온 auto_draft 는 TIER 1 과 밴드가 같지만 성격이 다르다 — 문구가 그 게시물 것이었다는 보장이 없다

TIER 4 · 게시물 미상 band template_only

반복 발송된 DM 템플릿은 확실히 찾았는데(서로 다른 대화 3개 이상), 어느 게시물의 캠페인인지 못 붙였다.

점수
confidence = 0.40 (고정)
저장 형태
media_id="" · 본문 URL 은 [링크] 로 치환
적용 시
사용자가 media_id 를 직접 지정해야 한다 (없으면 400)

TIER 5 · 복원 불가 band excluded — 후보로 만들지 않음

캠페인으로 감지는 됐는데 발송 이력을 못 찾았고 매칭 점수도 낮다. 대부분 바이럴 게시물이며, 페이징을 더 파도 복구되지 않는다(§7).

밴드 × 출처 = 2차원 (밴드만 보면 안 되는 이유)

auto_draftneeds_reviewtemplate_onlyexcluded
targeted TIER 1 실제 DM 원문 기반———
targeted_weak —TIER 2 원문은 근거로만——
global TIER 3 고점 추정TIER 3 저점 추정 TIER 4 미매칭 템플릿TIER 5

→ 프론트는 밴드로 정렬하되 배지는 dm_source 로 찍어야 한다. "실제 발송 DM에서 복원" vs "정황으로 추정" 을 같은 라벨로 묶으면 사용자가 추정 문구를 검수 없이 켠다.

2. DM 대화창을 어떻게 조회하는가 — 두 경로

경로 A · 타겟 조회 정확 — TIER 1·2 의 재료

게시물 댓글러의 IGSID 로 그 사람과의 대화방 하나만 직접 연다. 대화방 3만 개를 페이징할 필요가 없다.

GET /{ig-user-id}/conversations
    ?platform=instagram
    &user_id={댓글러 IGSID}
    &fields=id,messages.limit(25){id,created_time,from,to,message}

이게 성립하는 이유(실측 증명, 2026-07-21): 댓글의 from.id 와 메시징의 user_id 가 같은 IGSID 공간이다(겹침 11/20). 원래 계획서엔 "id-space 가 다를 것"이라 적혀 있었는데, 실측으로 기각됐다. 이 한 가지가 게시물↔DM 을 추론에서 관측으로 바꿨다.

그런데 "어느 댓글러를 고르냐"가 복원율을 22배 갈랐다. IG /comments 는 최신순 고정이고 order=chronological 이 무시된다(실측: 4월 게시물의 첫 페이지 댓글이 7월). 캠페인은 게시 직후 돌아가므로 DM 을 받은 사람은 "초기(오래된) 댓글러" 다. → 끝까지 페이징해 tail 을 취하면 복원율 38%, 첫 페이지(최신)만 쓰면 1.7%.

파라미터값이유
COMMENTS_OLDEST_MAX_PAGES10 (≈500댓글)tail 까지 페이징해 초기 댓글러 확보
TARGETED_PER_MEDIA12댓글러당 발신 DM 적중률이 ~6% 라 표본을 늘려야 커버리지가 오른다(6→12 로 복원 게시물 13→25)
예산 캡comments_oldest 400 · targeted_dms 600총 Graph 호출 상한 1500 안에서 배분

경로 B · 전역 스캔 표본 — TIER 3·4 의 재료

계정의 대화 목록을 커서로 훑어 발신 메시지만 모은다. 게시물 정보가 붙지 않아 사후 매칭이 필요하다.

GET /{ig-user-id}/conversations
    ?platform=instagram
    &fields=id,updated_time,messages.limit(20){id,created_time,from,to,message}
    &limit=25

⚠️ Meta 는 대화당 최근 ~20개 메시지 본문만 준다 → 오래된 최초 DM 은 누락될 수 있다. 그래서 이 경로는 '표본'으로 취급한다.

자기(TurnFlow) 발송 제외 — 3중 필터

이미 우리 서비스로 보낸 DM 이 "타사 캠페인 흔적"으로 잡히면 자기증식이 된다. 두 경로 모두 통과시킨다.

필터기준
① 메시지 IDSentDMLog.meta_message_id / echo_mid 와 일치
② 텍스트 지문sha1(placeholder_normalize(text)) 가 발송 로그·캠페인 템플릿 지문과 일치
③ 퍼지 매칭캠페인 템플릿과 difflib ratio ≥ 0.92 (길이차 30% 이내만 비교)
④ 노이즈 제외"팔로우했어요"·"안녕하세요"·"넵" 등 팔로우게이트 에코/인사, URL 없이 6자 미만 → 단, {url} 페이로드가 있으면 노이즈로 보지 않는다

④ 가 없던 시절 mini_ai_ 실데이터에서 "팔로우했어요"·"안녕하세요 🙂" 가 템플릿으로 잡혀 첫 DM 초안을 오염시켰다.

4. 우리 템플릿으로 어떻게 변환되는가

4-1. 개인화 토큰 → 슬롯 정규화

사람마다 다른 부분을 슬롯으로 치환해야 "같은 템플릿"으로 묶인다. 치환 순서가 중요하다(URL 안에 숫자가 있으므로 URL 먼저).

순서대상슬롯
1URL (http(s)://, www., *.com/net/co/kr/io/me/link/shop){url}
2이메일{email}
3휴대폰 번호{phone}
4@멘션{mention}
5이모지 블록{emoji}
6잔여 2자리 이상 숫자런{num}

그 뒤 NFKC·zero-width 제거·casefold·공백 축약. 이 정규화형이 군집 키이자 자기발송 지문(sha1)의 입력이다. 검출된 슬롯은 matched_template.variable_slots 로 후보에 남는다.

7. 복원 불가의 구조적 바닥 — 왜 100%가 안 되나

⚠️ 2026-08-13 정정 — 이 절의 결론은 2차 연구에서 기각됐습니다.

아래 "바이럴 게시물 원천 복원 불가"는 수집 버그가 만든 착시였습니다. DM 자동화 도구는 버튼 DM을 보내는데, 그 본문은 message 가 아니라 attachments.generic_template 에 들어갑니다. 수집기가 message 만 요청해서 발신 DM의 67~100%가 빈 문자열로 왔고, 파이프라인은 그걸 "보낸 DM 없음"으로 읽었습니다.

필드에 attachments 하나를 추가하자 아래에서 "복원 불가"로 지목된 게시물이 0/6 → 6/6, DM 0건 → 314건 으로 복원됐습니다. 전달은 되고 있었습니다. → docs/system/DM_MIGRATION_RESEARCH_R2.html 참조. 아래 원문은 이력 보존용으로 남깁니다.

바이럴 게시물은 원천적으로 복원 불가다. 댓글 600~4935개짜리 게시물들의 복원이 실패했다. "우리 페이징이 초기 댓글러를 못 봐서"라는 가설을 검증하려 상위 3개를 런칭일까지 파봤다(최대 80페이지·4000댓글, 게시일 근처 도달) — 그래도 초기 댓글러조차 DM 적중 0~1/15.

원인은 페이징이 아니라 도달 구조다. 바이럴 게시물은 도달이 커서 댓글러 대부분이 비팔로워 → 자동 DM(Private Reply)이 채널 미개설로 애초에 전달 실패 → 대화 자체가 없으므로 정렬·깊이와 무관하게 복원할 대상이 없다. 반대로 작고 타게팅된 게시물은 팔로워 댓글러 비중이 높아 잘 복원된다. → 캡을 올리는 건 API 낭비. 현재 캡이 합리적이다.

제품 함의: "감지 N개 중 M개만 내용 복원"이 정상 동작이다. 프론트가 이걸 솔직하게 보여줘야 한다 — 복원 실패 게시물은 "캠페인으로 보이나 발송 이력 없음 → 첫 DM 직접 작성" 으로 needs_review 노출하는 게 맞다(현재는 excluded 처리).
