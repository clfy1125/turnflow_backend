4. 2534022 — 5명이 보상 DM 을 못 받았습니다

구조부터 이해가 필요합니다.

  • 댓글은 24시간 대화창을 열지 않습니다. 댓글은 “비공개 답장 1회 권한”(7일)일 뿐입니다.
  • 그래서 첫 DM(오프닝)은 늘 잘 갑니다 — 댓글 권한으로 보내니까요.
  • 보상 DM 은 24시간 창이 필요하고, 그 창을 여는 건 상대가 버튼을 누른 행위 하나뿐입니다.
  • Meta 가 그 탭을 간헐적으로 “우리(비즈니스)가 보낸 것”으로 잘못 기록합니다 → 창이 안 열림 → 보상 DM 거부.

실측 5건: 2건은 오프닝 도착 0–2분 뒤 탭인데 거부, 3건은 16시간–2일 뒤 탭. 탭 자체가 창을 열어야 하므로 경과 시간과 무관하게 같은 원인입니다. 자동 재시도(20초·1분·3분)를 전부 소진했고, 재탭이 없어 되살림도 발동하지 않았습니다.

규모: 30일 보상 DM 30,523건 중 5건(0.016%). 2026-08-07 패치 직후엔 0건이었으니 “다시 조금 생긴” 상태입니다.

남은 빈틈은 “다시 눌러달라고 알려줄 방법이 없다”는 것. 창이 닫혀 DM 은 못 보내지만 댓글 API 는 살아 있으므로, 기존 ‘실패 DM 복구’(공개 대댓글로 유도)를 보상 DM 실패에도 붙이는 것이 유일한 자력 복구 경로입니다.

7. 무엇을 고쳤나 (2026-08-31 패치)

5장의 “도착했는데 실패로 기록되는” 문제를 증거가 오는 두 시점에서 받아먹도록 고쳤습니다. 추가 API 호출은 0회입니다 — 이미 우리에게 오고 있던 신호를 버리고 있었을 뿐입니다.

① 에코 웹훅을 버리지 않는다

Meta 는 실제로 배달된 메시지의 is_echo 웹훅을 몇 초 안에 보냅니다. 실측: 문제의 08-28 건은 로그 생성 12초 뒤 에코가 실제로 도착해 있었습니다(EventInbox 2건). 그런데 매칭 규칙이 “message_id 일치” 또는 “그 수신자의 ACCEPTED 로그”뿐이라, message_id 를 못 받은 바로 그 발송에는 붙을 곳이 없어 그냥 버려졌습니다.

이제 어디에도 안 붙는 에코는 “우리가 보냈는데 응답을 못 받은 발송”의 증거로 씁니다. 안 보낸 DM 을 ‘보냈다’고 표시하지 않도록 자물쇠를 넷 걸었습니다 — 같은 계정·같은 수신자 / message_id 공란 / 15분 안에 실제로 POST 한 적 있음 / 이미 결론 안 난 시도가 1회 이상.

부수 효과가 하나 더 있습니다: 재시도 대기 중인 건이 승격되면 예약된 재시도가 발송 진입 가드에 걸려 재발송 자체가 사라집니다 → “이미 답글”(2534023) 오류를 애초에 만들지 않습니다.

② 버튼 탭도 증거로 쓴다

팔로우게이트 버튼은 그 DM 안에 있습니다. 탭이 왔다는 건 DM 이 도착했다는 뜻입니다. 이제 탭을 처리할 때 오프닝 로그가 “증거 없는 실패·대기”면 도착으로 정정합니다. 이미 통과(PASSED)한 재탭에서도 정정되도록 게이트 처리보다 앞에 뒀습니다.

같이 막은 이중 계상

승격 뒤 기존 Conversations 승격 경로가 또 들어오면 상태를 ACCEPTED 로 되돌리고 발송 수를 두 번 셀 수 있었습니다 → 이미 도착한 로그면 아무것도 하지 않도록 가드를 넣었습니다. 통계 보정(발송 +1 / 미확인 −1)도 이전 상태에 따라 달라 한 곳에서만 판단하게 모았습니다.

  • 가드 10건은 패치 전후 모두 통과 — 안 보낸 DM 은 절대 승격되지 않습니다 (미발송·창 밖·발송 중·다른 계정·창 만료 실패).
