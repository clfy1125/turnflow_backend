DM 오류 처리방침 분류표 — 전수 · 쉬운 설명판

자동 DM 이 실패하거나 건너뛰어지는 모든 경우 51가지를 한 줄씩 뽑고, 각각 무슨 일이 벌어진 건지 · 고객 화면엔 어떻게 보이는지 · 우리가 뭘 해야 하는지를 붙였습니다. 아래 5개 버킷 중 하나를 고르면 자동 저장됩니다. 기본값은 이미 채워져 있으니 바꿀 것만 바꾸시면 됩니다.

0. 먼저 — 자동 DM 한 통이 나가는 전체 과정

아래 7단계 중 어느 단계에서 멈췄느냐가 곧 오류 종류입니다. 빨간 글씨가 그 단계에서 생기는 실패입니다.

STEP 1누가 댓글을 답니다 인스타가 우리 서버로 "댓글 달렸다"고 알림(웹훅)을 보냅니다. 알림 누락 → 매시간 보정 배치가 주움
STEP 2캠페인 조건 확인 키워드가 맞는지, 캠페인이 켜져 있는지, 발송 시간대인지 봅니다. 여기서 취소 = "건너뜀(skipped)" ④번 섹션
STEP 3발송 줄 세우기(큐) 인스타가 한 번에 많이 못 보내게 하므로 3~8초 간격으로 천천히 보냅니다. 기다리는 사이 24시간이 끝날 수 있음
STEP 4토큰 확인 후 호출 인스타 로그인 열쇠(토큰)가 살아 있는지 보고 API 를 부릅니다. 열쇠 죽었으면 호출도 안 하고 실패 처리
STEP 5인스타 응답 성공이면 메시지 번호를 줍니다. 실패면 오류 번호(code/subcode)를 줍니다. ①②③번 섹션의 대부분이 여기
STEP 6진짜 도착했는지 35분간 추적 "접수했다"는 답과 실제 도착은 다릅니다. 웹훅·대화 조회로 확인합니다. 흔적 없으면 "도착 미확인"
STEP 7최종 상태 확정 도착 / 읽음 / 실패 / 숨겨진 요청 중 하나로 굳습니다. 복구 기능이 켜져 있으면 일부는 재도전
용어 사전 — 표에 나오는 말 (모르는 단어 있으면 여기부터)
code / subcode오류 번호

인스타가 실패할 때 주는 번호 두 개. code는 큰 분류(예: 100 = 값이 잘못됨), subcode는 세부 이유(예: 2534022 = 24시간 지남). subcode 가 있으면 원인이 확실하고, 없으면 큰 번호만으로 추측해야 합니다.

status우리가 붙이는 상태

인스타 번호를 보고 우리 서버가 결론 내린 상태값. failed_token(열쇠 문제), failed_window(24시간 끝남), failed_param(값 문제), failed_no_trace(도착 확인 못 함) 등. DB 의 SentDMLog.status 컬럼에 저장됩니다.

비공개 답장Private Reply

"댓글에 대한 답으로 DM 을 보내는" 인스타 전용 기능. 우리 자동 DM 의 핵심입니다. 제약 2개: 댓글 1개당 딱 1번, 댓글 달린 지 7일 이내.

24시간 창messaging window

상대가 우리에게 반응(댓글·DM·스토리답장)한 시점부터 24시간 안에만 DM 을 보낼 수 있다는 인스타 정책. 지나면 상대가 다시 반응해야 열립니다. 우리 잘못이 아니라 정책입니다.

토큰access token

고객이 인스타 연동할 때 받는 로그인 열쇠 문자열. 60일이면 만료되고, 비밀번호 변경이나 권한 해제로도 죽습니다. 죽으면 그 계정의 DM 이 전부 멈춥니다 → 고객이 재연동해야 함.

숨겨진 요청 / 스팸함

서로 팔로우가 아닌 사람에게 처음 DM 을 보내면, 바로 대화방에 안 들어가고 상대의 "메시지 요청" 탭으로 갑니다. 상대가 수락해야 진짜 도착입니다. 실패는 아니지만 도착도 아닌 애매한 상태.

복구recovery

위 "숨겨진 요청"으로 간 건을 구제하는 우리 기능(프로 플랜 전용). 그 댓글에 공개 답글로 "요청함에서 수락하고 다시 댓글 달아주세요"를 남기고, 다시 댓글이 오면 자동 재발송합니다.

도착 미확인failed_no_trace

인스타가 "접수했다"고 답은 했는데, 35분을 지켜봐도 실제로 도착한 흔적이 없는 상태. 실패로 세지만 재검증(reverify) 버튼으로 다시 확인해서 성공으로 되돌릴 수 있습니다.

건너뜀skipped

인스타에 요청조차 안 보내고 우리가 스스로 취소한 것. 실패가 아니라 "시작 안 함"입니다. 월 한도 소진, 캠페인 정지, 발송 시간대 밖 등이 여기 해당합니다.

레이트 리밋rate limit

"너무 빨리 많이 부르지 마라"고 인스타가 잠깐 막는 것. 실패가 아니라 지연이며 서버가 알아서 나중에 다시 시도합니다.

폴백fallback

"딱 맞는 게 없을 때 쓰는 차선책". 우리 오류 사전은 ①(code+subcode) → ②(code+status) → ③code → ④status 순으로 찾고, 앞에서 못 찾으면 뒤로 내려갑니다. 뒤로 갈수록 설명이 뭉뚱그려집니다.

레거시legacy

"지금은 안 쓰는데 옛날 데이터/코드가 남아 있는 것". 과거 기록이면 그냥 두면 되지만, 최근 날짜로 새로 찍히면 버그입니다.

센티넬sentinel

진짜 값이 없을 때 "값 없음"을 나타내려고 자리에 끼워 넣는 표식용 가짜 값. 이 표에 하나 나오는데, 실제로는 안 쓰이는 걸로 보입니다.

오류 사전dm_error_catalog.py

번호를 한국어 원인·조치 문구로 바꿔주는 서버 쪽 표. 여기 없으면 운영 화면 팝업에 설명이 빈칸으로 나옵니다. 이 HTML 이 바로 그 사전의 전수 목록입니다.

분류 5가지 — 무슨 뜻인가

🔴 확인해야함원인을 아직 모르는 것. 로그 원문을 열어보거나 코드를 봐야 답이 나옵니다. "일단 조사 대상" 서랍.
🟠 사용자 조치고객이 직접 해야 풀립니다. 우리는 안내만 가능 — 재연동 / 플랜 업그레이드 / 인스타 설정 변경.
🔵 관리자 조치우리(운영팀) 손이 필요합니다 — 재검증 버튼, 중복 캠페인 정리, 게시물 교체 안내, 영업 연락.
🟣 수신자 사정상대방 계정 문제라 우리도 고객도 못 고칩니다. 비율만 지켜봅니다.
⚪ 정책상 정상설계·정책대로 동작한 것. 아무것도 안 해도 됩니다.
🙋 "설명 더 필요" 버튼 — 읽어도 이해가 안 되거나 판단이 안 서는 행은 각 줄 오른쪽의 🙋 설명 더 필요 를 눌러주세요. 분류(빨강/주황/…)와 따로 기록돼서, 내보내기 JSON 에 needs_explanation: true 로 나옵니다. "조사해야 할 오류(🔴)"와 "설명이 부족한 항목(🙋)"을 섞지 않으려고 나눠 뒀습니다.
