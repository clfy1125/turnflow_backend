해석: 캠페인이 항상 게시 직후에 켜지는 게 아닙니다

보통은 게시물을 올리면서 캠페인을 켭니다. 그래서 게시 직후 댓글러가 DM을 받습니다 — 5차 연구의 발견.

그런데 나중에 켜는 경우도 있습니다. 예전 게시물이 갑자기 잘 되기 시작하면 그때 캠페인을 붙이는 식입니다. 그러면 그 시점 이후 댓글러가 DM을 받고, 초기 댓글러는 못 받습니다. 5월 19일 게시물이 정확히 이 경우로 보입니다.

그래서 "무조건 오래된 댓글러"도 틀렸습니다

1차 연구는 "최신 댓글러만 보면 안 된다"고 했고 그건 맞았습니다. 그런데 제가 이번에 "오래된 댓글러만 보면 된다"로 뒤집은 것도 마찬가지로 틀렸습니다. 정답은 둘 다 보는 것입니다 — 캠페인이 언제 켜졌는지는 알 수 없으니까요.

6. 그래서 올바른 설계

이번 실행으로 세 가지가 분명해졌습니다. 이걸 합치면 이렇게 됩니다.

  1. 댓글 1페이지만 받고, 3명 조회한다 — 단 "섞어서"
    최근 댓글러 1~2명 + 그 페이지에서 가장 오래된 댓글러 1~2명. 캠페인이 언제 켜졌든 한쪽은 걸린다. 대부분의 게시물이 여기서 끝난다(실측: 보통 게시물은 거의 100% 적중)
  2. 0건이면 그때 댓글을 캠페인 기간까지 판다
    여기서 대형 게시물이 살아난다. 실측: 8페이지까지 파면 3명 조회로 복원. 이 단계에 들어오는 게시물은 소수라 전체 비용에 거의 영향이 없다
  3. 그래도 0건이고 캠페인 물증이 있으면, 반대쪽(최근)도 더 조회한다
    5월 19일 같은 "나중에 켠 캠페인"을 잡는 단계
  4. 물증도 없고 0건이면 종료
    캠페인이 없었던 것으로 확정. 실측으로 이런 게시물이 실제로 존재한다(전수조사 0 확정 4개)

8. 정리

질문답
최적화가 효과가 있었나? 대형 게시물에는 확실히. 이전에 20명을 봐도 못 찾던 것을 3명으로 찾았다. @highestlevel33 은 15.2분 → 7.9분으로 절반이 됐다
전체 시간이 줄었나? 아니다. 이미 잘 되던 계정에서 오히려 늘었다(5.6 → 6.4분). 적용 위치가 틀렸다
복원율이 올랐나? 같은 게시물 기준으로는 올랐다(실패 11개 중 4개 구제). 계정 전체 숫자(78% vs 74%)는 검사 대상이 달라 비교 불가
다음에 뭘 해야 하나? 후페이징 + 혼합 표본으로 고쳐서 재측정. 예상 3~3.5분(현재 5.5분)
이번 연구에서 배운 것 (방법론)

"A가 문제였다"를 찾았다고 해서 "항상 A를 하라"가 되지는 않습니다. 5차 연구에서 "깊은 댓글 파기"가 대형 게시물을 살렸더니, 저는 그걸 모든 게시물의 기본값으로 만들었습니다. 그 결과 필요 없는 곳에서 비용을 쓰고, "오래된 댓글러만" 보다가 정반대 케이스를 놓쳤습니다. 발견은 조건부로 적용해야 합니다 — "실패했을 때만", "양쪽 다".

방식: prod 읽기 전용(Graph API GET + DB 읽기). DM 발송·데이터 쓰기·코드 배포 없음. 연구 스크립트 probe17_optimized.py(세션 임시 폴더, 미커밋).
