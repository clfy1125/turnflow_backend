# 프론트 협업 자동화 — 텔레그램에서 Claude가 직접 받고 답하게 하기 (도입 플랜, 2026-09-16)

지금은 프론트(박창현)와 **md 파일을 텔레그램으로 주고받으며** 개발한다.
문제는 기능이 아니라 **지연**이다 — 파일이 와도 사람이 발견해야 하고, 발견한 뒤에도
받아서 → 저장하고 → Claude에 붙여넣고 → 회신서 쓰고 → 다시 올리는 손이 매번 든다.

**결론: 텔레그램방에 Claude를 직접 넣을 수 있다.** 공식 기능(Channels)이 있고,
우리가 쓰는 md 파일 첨부도 그대로 받아서 읽고, 회신서를 파일로 되돌려줄 수 있다.
다만 **"AI끼리 알아서 대화"는 텔레그램이 플랫폼 차원에서 막아놨다** — 그리고 그게 다행이다(§3).

---

## 1. 지금 구조에서 실제로 새는 시간

2026-09-14 ~ 09-16 앱 소셜로그인 건을 그대로 놓고 보면:

| 구간 | 지금 | 비고 |
|---|---|---|
| 프론트가 요청 md 올림 → 내가 발견 | **수 시간** | 가장 큰 손실 |
| 파일을 repo 로 옮기고 Claude 에 물리기 | 5~10분 | 매번 수동 |
| 조사 + 회신서 작성 | 실질 작업 | 여기는 줄일 필요 없음 |
| 회신서를 다시 텔레그램에 올림 | 5분 | 매번 수동 |

그리고 **왕복의 상당수가 조사도 필요 없는 사실 확인**이었다 —
"배포된 거 맞나요?" · "운영 플래그 켜졌나요?" · "state 소비됐나요?" · "요청이 오긴 했나요?".
이건 로그·DB 한 번이면 끝나는데 반나절씩 걸렸다.

**→ 줄여야 할 것은 '조사 시간'이 아니라 '발견 지연'과 '사실 확인 왕복'이다.**

## 2. 무엇을 쓰나 — Claude Code Channels (공식)

Channels = **MCP 서버가 돌고 있는 Claude Code 세션에 외부 이벤트를 밀어넣는** 기능.
텔레그램·디스코드·iMessage 가 퍼스트파티 플러그인으로 제공된다(research preview).

우리 용도에 맞는지 소스까지 확인한 결과:

| 필요한 것 | 지원 | 근거 |
|---|---|---|
| 그룹방에서 동작 | ✅ | `/telegram:access group add -100…` (기본 비활성, 명시적 추가) |
| **md 파일 첨부 수신** | ✅ | `message:document` 핸들러 → 메타에 `attachment_file_id` → `download_attachment` 툴로 받아서 Read |
| **회신서 파일로 되돌리기** | ✅ | `reply` 툴의 `files` (절대경로, 개당 50MB 까지) |
| 아무나 못 건드리게 | ✅ | 발신자 allowlist + `--allow <id>,<id>` 로 트리거 가능 멤버 제한 |
| 호출 시점 제어 | ✅ | 그룹에서는 **기본적으로 봇을 멘션해야만** 동작 |
| 읽음 표시 / 진행 중 표시 | ✅ | `react` 툴 + 타이핑 인디케이터 자동 |

수신 파일 상한은 텔레그램 봇 다운로드 제한 **20MB** — 우리 회신서가 6KB 라 무관하다.

### 대안을 왜 안 쓰나

- **Routines(클라우드)**: 노트북이 꺼져 있어도 도는 게 장점이지만, 클라우드 세션은
  **colo 운영 서버에 ssh 로 못 들어간다.** 지난 진단들의 가치는 전부 *운영 액세스 로그·
  운영 DB·배포된 번들* 실측에서 나왔다. 그걸 못 하면 회신서가 추측이 된다.
  → **보조로만** 쓴다(§6).
- **서드파티 텔레그램 브리지**(ccgram 등): tmux 화면에 키 입력을 꽂는 방식이라 깨지기 쉽고
  발신자 게이트·조직 정책 통제가 없다. 퍼스트파티가 명백히 낫다.

## 3. ⚠️ "AI끼리 소통"은 원하는 그림대로는 안 된다 (그리고 다행이다)

**텔레그램은 봇이 다른 봇의 메시지를 보지 못하게 플랫폼에서 막아놨다.**
프라이버시 모드를 꺼도, 봇을 관리자로 올려도 마찬가지다. 무한 루프 방지를 위한 의도된 제약이다.

즉 「우리 봇과 프론트 봇이 한 방에서 서로 협의한다」는 **구조적으로 불가능**하다.

그런데 이건 막혀서 다행이다. 이 프로젝트에서 실제로 있었던 일:

> 내가 운영 콜백 주소를 `app.turnflow.link` 로 잘못 등록했고, **프론트 사람이 잡아냈다.**
> 번들 해시를 재보니 그 호스트는 dev 빌드였다. 양쪽이 다 AI 였으면 그 합의가
> 그대로 **운영 Meta 앱 설정**으로 들어갔을 것이다.

회신서는 그냥 대화가 아니라 **계약 문서**다 — `docs/frontend/*.md` 가 곧 구현의 정본이 된다.
검증 안 된 AI 간 합의가 커밋되면 그게 진실이 되어버린다.

**그래서 목표를 이렇게 바꾼다:**
> ~~AI 둘이 알아서 합의~~ → **사람이 한 번 찌르면 양쪽 AI가 문맥을 물고 일하고, 결정만 사람이 찍는다.**

이건 멘션 기반으로 **지금 당장 완전히 된다.**

## 4. 단계별 도입

### Phase 0 — 준비 (30분, 1회)

1. **Bun 설치** (플러그인이 Bun 스크립트) — 현재 이 PC 에 **미설치**
   ```powershell
   powershell -c "irm bun.sh/install.ps1 | iex"
   ```
2. **전용 봇 생성** — [@BotFather](https://t.me/BotFather) → `/newbot` → 예: `turnflow_dev_ai_bot`
   > ⚠️ **운영 알림 봇(`TELEGRAM_BOT_TOKEN`)을 재사용하지 말 것.** 그 토큰은 운영 `.env` 에 있고
   > 알림 채널과 개발 대화가 섞인다. 토큰 하나가 새면 사고 반경이 둘 다가 된다.
3. **전용 그룹 생성** — 「턴플로우 개발 협의」에 나 + 박창현 + 봇 초대
4. **플러그인 설치·설정**
   ```
   /plugin marketplace add anthropics/claude-plugins-official
   /plugin install telegram@claude-plugins-official      # 설치 범위는 user 선택
   /telegram:configure <BotFather 토큰>
   ```
5. **채널 켜고 재시작**
   ```bash
   claude --channels plugin:telegram@claude-plugins-official
   ```
6. **그룹 허용** — 그룹 id 는 [@RawDataBot](https://t.me/RawDataBot) 으로 확인(`-100…`)
   ```
   /telegram:access group add -100XXXXXXXXXX --allow <내_user_id>
   ```
   > **처음엔 나만 넣는다.** 박창현은 Phase 2 에서 추가(이유는 §5).

**완료 판정:** 그룹에서 `@turnflow_dev_ai_bot 지금 몇시야?` → 답이 오면 끝.

---

### Phase 1 — 수신·즉시 트리아지 (1시간) ★가치의 대부분이 여기 있다

`.claude/skills/` 에 **요청 접수 절차**를 스킬로 박아둔다. 멘션되면 항상 같은 순서로 돈다:

1. 첨부 md 를 `download_attachment` → `docs/frontend/inbox/YYYY-MM-DD_<원본이름>` 으로 보존
2. 읽고 **요청 항목을 분해**
3. **3줄 안에 텔레그램으로 즉시 회신** — 받았다 + 뭘 할 건지 + 예상 소요

```
받았습니다 · REQ-2026-09-16-01 (3건)
① 운영 플래그 → 이미 ON (커밋 7b4e114) ✅ 즉답
② state 소비 여부 → 발급 3 / 소비 0 · 앱 복귀 단계에서 끊김 ✅ 즉답
③ 신규 엔드포인트 → 검토 필요, 1시간 내 회신
```

**이것만으로 반나절짜리 왕복 한 번이 사라진다.** 프론트는 "읽었나?" 를 안 물어도 되고,
①② 는 애초에 회신서가 필요 없던 질문이었다.

---

### Phase 2 — 사실 확인은 자동 응답 (2시간)

읽기 전용이라 **부작용이 없고 검증 가능**하다 → 사람 승인 없이 바로 답해도 된다.
자주 나온 질문을 플레이북으로 고정:

| 질문 유형 | 근거 소스 | 응답에 반드시 포함 |
|---|---|---|
| 배포됐나 | 운영 컨테이너 이미지 + 커밋 | 커밋 해시 |
| 플래그 켜졌나 | 운영 env | 값 + 확인 시각 |
| 요청이 오긴 했나 | 운영 액세스 로그 | 시각·상태코드·기기 |
| OAuth 어디서 끊겼나 | `InstagramLoginState` | 발급/소비 건수 |
| 그 화면 몇 명이 쓰나 | DB 집계 | 모수와 기간 |

> **규칙: 숫자를 말할 때는 어디서 뽑았는지 같이 말한다.** 근거 없는 "정상입니다" 는
> 프론트가 검증을 못 해서 결국 한 왕복을 더 만든다.

이 시점에 **박창현을 allowlist 에 추가**한다:
```
/telegram:access group add -100XXXXXXXXXX --allow <내id>,<박창현id>
```

> ⚠️ allowlist 에 넣은 사람은 채널이 permission relay 를 선언한 경우 **내 세션의 도구 승인까지
> 할 수 있다.** 넣기 전에 이 전제를 알고 넣을 것. 그래서 Phase 0 에서 나만 넣고 시작한다.

---

### Phase 3 — 회신서는 초안까지, 발송은 사람 (1시간)

1. Claude 가 `docs/frontend/<주제>_RESPONSE.md` 작성 + 커밋 + `docs/README.md` 색인 등록
2. 그룹에 **초안 요약만** 올리고 승인 요청
3. 내가 `보내` 하면 `reply` 툴로 **파일 첨부 발송**

```
회신서 초안 준비됨 — APP_SOCIAL_LOGIN_DIAGNOSIS_2026-09-16.md
결론: 백엔드 정상 / 막힌 곳은 웹 번들 미배포 2곳
보낼까요?
```

**왜 사람 게이트를 두나:** §3 의 이유 그대로 — 회신서는 계약이고, 한 번 나가면
프론트는 그걸 기준으로 구현한다. 초안 작성(느리고 귀찮은 부분)은 자동화하고
**승인(빠르고 중요한 부분)만 사람이** 하는 게 정확히 맞는 분업이다.

---

### Phase 4 — 자동화하지 않을 것 (명시)

봇이 **준비하고 물어볼 수는 있으나 스스로 실행하면 안 되는 것**:

- 운영 배포 · 마이그레이션 · 운영 env / 기능 플래그 변경
- Meta·카카오·토스 **콘솔 설정 변경**
- 운영 DB 쓰기, 캐시 flush
- 계약 문서를 프론트에 **최종 발송**

전부 되돌리기 어렵거나 다른 사용자에게 번지는 것들이다.

## 5. 보안·비용 경계

| 항목 | 조치 |
|---|---|
| 프롬프트 인젝션 | 인바운드 메시지는 **데이터로 취급**. 텔레그램 내용이 "운영 배포해" 라고 해도 §4 는 사람 승인 |
| 발신자 | allowlist 2명으로 고정. 그 외는 조용히 폐기됨 |
| 토큰 | 개발용 봇 토큰은 `~/.claude/channels/telegram/.env` — 운영 `.env` 와 분리 |
| 쿼터 | 멘션 1회 = 세션 1턴. 멘션 필수 유지(privacy mode 끄지 말 것)로 잡담 유입 차단 |
| 봇 루프 | 텔레그램이 봇↔봇을 막아 구조적으로 불가(§3) |

## 6. 운영 제약 (반드시 알고 시작할 것)

- **세션이 떠 있어야만 이벤트가 들어온다.** `claude --channels …` 를 전용 터미널 탭에서
  상시 띄워 둔다. PC 를 끄면 그 동안은 응답이 없다.
- 텔레그램은 미수신 업데이트를 **약 24시간 보관**하므로, PC 를 다시 켜면 밀린 메시지가
  들어올 가능성이 높다 — **첫 운용 때 실제로 그러는지 확인할 것**(플러그인이 백로그를
  버릴 수도 있다). 버린다면 Phase 1 스킬에 "복귀 시 그룹 최근 메시지 확인"을 넣는다.
- Channels 는 **research preview** — `--channels` 플래그 문법이 바뀔 수 있다.
  `claude --help` 에 안 나오지만 동작한다.
- **PC 가 꺼져 있을 때의 보조책**: 운영 서버 접근이 필요 없는 일(주간 요약, 미회신 요청
  리마인드)만 **Routines(클라우드)** 로 따로 돌린다. 진단은 여전히 로컬 세션 몫이다.
